# Branes et numérologie — couche symbolique

## But

Documenter une analogie interne du projet sans la confondre avec le graphe psycho-causal ni avec une équivalence physique démontrée.

---

## 1. Principe

La hiérarchie des branes sert de métaphore **macro → micro** et de langage de niveaux.

La numérologie inversée fournit les dualités :

```text
9 <-> 1
8 <-> 2
7 <-> 3
6 <-> 4
5 = pivot
```

Le rapprochement peut être utilisé pour visualiser des symétries ou élaborer des hypothèses de sens.

---

## 2. Séparation obligatoire

```text
Soul Graph = modèle psycho-causal
1→9 = projection topologique
numérologie = hypothèses archétypales
branes = couche analogique
```

Aucune correspondance brane/chiffre ne crée automatiquement une relation `activates`, `causes` ou `inhibits`.

---

## 3. Stockage

Si cette couche est stockée dans Kristal, les assertions doivent être marquées comme modèle symbolique/interprétatif selon le profil actif.

---

## 4. Usage recommandé

- documentation philosophique ;
- visualisation ;
- génération d’hypothèses ;
- comparaison de structures.

Pas :

- validation de la personnalité ;
- preuve physique ;
- moteur direct de réaction.

# Référence du code — implémentation Soul Graph

## Statut

La migration du prototype vers le modèle Soul Graph est maintenant implémentée dans `src/`.

Le code demeure une **implémentation de référence minimale** : il fournit le modèle de données, la propagation déterministe, les snapshots, les transformations biographiques explicites, les hypothèses symboliques et l'adaptateur Kristal. Il ne contient pas encore de parseur sémantique avancé ni de moteur de rendu capable d'imiter finement la voix d'une personne.

## Modules

- `src/models.py` — `SoulNode`, `SoulEdge`, `SoulGraph`, `SoulSnapshot`, `Stimulus`, `ReactionState`.
- `src/soul_graph.py` — prédicats causaux, validation, IDs déterministes, construction des snapshots.
- `src/activation.py` — ancrage lexical/explicite, propagation bornée, inhibition, affect et tendances de réaction.
- `src/engine.py` — orchestration `SoulSnapshot + Stimulus -> ReactionState`; le snapshot reste inchangé.
- `src/evolution.py` — création **explicite** d'un snapshot ultérieur; jamais appelée automatiquement par `react()`.
- `src/hypotheses.py` — propositions symboliques, dont natal chart, marquées `hypothesized_innate`.
- `src/numerology.py` — calculs numérologiques historiques, utilisés comme source d'hypothèses.
- `src/projections.py` — `TraitVector` dérivé du graphe.
- `src/kristal.py` — projection vers un `Structured Epistemic State` de forme Kristal v5 et retour.
- `src/renderer.py` — renderer déterministe minimal de debug.
- `src/safety.py` — couche de sécurité externe à la personnalité.
- `src/ethics.py` — shim de compatibilité déprécié; ignore les traits du personnage.
- `src/interpolation.py` — utilitaires historiques 1→9, conservés comme projection secondaire.
- `src/ontology.py` — lecture robuste de l'ontologie historique `pi_ontology.json`.

## API minimale

```python
from src.engine import ArtificialSoulEngine
from src.models import SoulNode, SoulEdge
from src.soul_graph import make_edge_id

engine = ArtificialSoulEngine()

nodes = [
    SoulNode("concept:dog", "Concept", "chien"),
    SoulNode("assoc:danger", "Association", "danger", origin="acquired"),
    SoulNode("reaction:avoid", "ReactionPattern", "évitement",
             properties={"tendency": "avoid"}),
]

edges = [
    SoulEdge(make_edge_id("concept:dog", "activates", "assoc:danger"),
             "concept:dog", "activates", "assoc:danger", {"strength": 0.8}),
    SoulEdge(make_edge_id("assoc:danger", "predisposes_to", "reaction:avoid"),
             "assoc:danger", "predisposes_to", "reaction:avoid", {"strength": 0.8}),
]

snapshot = engine.build_snapshot(
    person_id="person:example",
    nodes=nodes,
    edges=edges,
    valid_during={"age": 30},
)

result = engine.react(snapshot=snapshot, stimulus="Un chien arrive.")
```

La sortie comprend `reaction_state`, la trace d'activation, le texte de debug optionnel et l'information de sécurité externe.

## Évolution biographique

```python
from src.evolution import derive_snapshot

later = derive_snapshot(
    snapshot,
    valid_during={"age": 40},
    add_nodes=[...],
    remove_node_ids=[...],
    biographical_causes=[...],
)
```

Cette opération crée un nouvel objet et place `snapshot.snapshot_id` dans `source_snapshot_ref`.

## Hypothèses natal chart

Le projet ne définit pas encore de calcul astrologique normatif. Il fournit plutôt une frontière explicite : un calculateur externe peut produire des `SymbolicProposal`, qui restent des hypothèses identifiables et peuvent être exclues du moteur par `EngineConfig(include_hypothesized=False)`.

# Définition opérationnelle — Âme Artificielle

## 1. But

Définir une représentation implémentable, testable et traçable d’une personnalité sans prétendre créer une âme réelle.

La définition opérationnelle est :

```text
Âme Artificielle = Soul Snapshot + moteur d’activation
```

Le snapshot contient la structure persistante. Le moteur calcule un état transitoire à partir d’un stimulus.

---

## 2. Modèle minimal

### Soul Basis
Vocabulaire commun des types de nœuds, relations et règles d’interprétation.

### Soul Snapshot
Graphe psycho-causal immuable d’un sujet pendant une période.

### Activation Graph
Sous-graphe temporaire produit pour une interaction.

### Reaction
Sortie structurée dérivée de l’activation.

---

## 3. Invariants

1. **Pas d’auto-update de personnalité** : `react()` ne modifie pas le Soul Snapshot.
2. **Les émotions présentes sont transitoires** : elles appartiennent à l’Activation Graph sauf justification explicite contraire.
3. **Les traits sont dérivés** : un `TraitVector` est une projection du graphe.
4. **La sécurité est externe** : elle ne fait pas partie de la causalité de l’âme.
5. **Les hypothèses symboliques restent identifiables** : numérologie et natal chart ne sont pas fusionnés silencieusement avec les observations.
6. **La provenance est conservée** : chaque assertion importante doit pouvoir être reliée à une source ou à une méthode de dérivation.
7. **Force psychologique ≠ certitude épistémique**.

---

## 4. Graphe psycho-causal

Un snapshot est un graphe dirigé, typé et potentiellement cyclique.

Nœuds minimaux :

```text
Disposition
Belief
Association
Value
Need
Attachment
Memory
Concept
InterpretationPattern
CognitiveBias
IntellectualRule
AffectiveTendency
ReactionPattern
Event
Context
Person
Group
```

Relations minimales :

```text
activates
inhibits
reinforces
weakens
predisposes_to
contributes_to
interprets_as
contradicts
confirms
generalizes_to
formed_by
revised_by
supersedes
```

Voir `docs/soul_graph_schema.md`.

---

## 5. Âme, intellect, personnalité

- **Âme** : organisation profonde des dispositions et rapports.
- **Intellect** : mécanismes de perception, raisonnement, croyance explicite et réévaluation.
- **Personnalité** : manifestation observable de l’âme et de l’intellect dans une histoire et un contexte.

Cette séparation est conceptuelle : les deux familles de mécanismes peuvent être représentées dans un même graphe avec des types distincts.

---

## 6. Temps

Un snapshot porte :

```text
person_id
snapshot_id
valid_during
source_snapshot_ref (optionnel)
```

Un nouveau snapshot est produit lorsqu’on veut représenter un état ultérieur de la personne.

Les causes proposées du changement sont stockées comme assertions biographiques, pas seulement comme métadonnées de version.

---

## 7. Entrées

Entrées possibles pour construire un snapshot :

- biographie ;
- témoignages ;
- écrits ou paroles de la personne ;
- observations structurées ;
- données psychométriques ;
- numérologie — couche hypothétique ;
- carte du ciel — couche hypothétique ;
- règles éditoriales explicites.

Le moteur de réaction reçoit ensuite :

```text
snapshot + stimulus + contexte
```

---

## 8. Sorties

Le moteur devrait produire une structure avant le texte :

```json
{
  "interpretation": [],
  "active_nodes": [],
  "active_paths": [],
  "affective_state": {},
  "intentions": [],
  "reaction_tendencies": [],
  "trace": {}
}
```

Le texte est une représentation de cette structure.

---

## 9. Non-objectifs

- prouver une âme métaphysique ;
- déclarer qu’un système ressent une émotion parce qu’il en reproduit la dynamique ;
- diagnostiquer une personne ;
- faire de l’astrologie ou de la numérologie une vérité par convention ;
- permettre à une conversation fictive de réécrire automatiquement un modèle biographique.

---

## 10. Critères de réussite

- **cohérence intra-snapshot** ;
- **contraste inter-personnes** ;
- **contraste intra-personne entre âges**, lorsque documenté ;
- **traçabilité des réactions** vers les mécanismes du graphe ;
- **reproductibilité** avec mêmes données et même configuration ;
- **validation séparée des hypothèses symboliques**.

# Engine Spec — Soul Causal Engine

## 0. Portée

Cette spécification remplace le modèle où la personnalité était principalement un `TraitVector` modulé par un axe 1–9.

Le moteur prend :

```text
SoulSnapshot + Stimulus + Context
```

et produit :

```text
ActivationGraph + ReactionState
```

sans modifier le snapshot.

---

## 1. Responsabilités

Le moteur doit :

1. charger un snapshot ;
2. analyser sémantiquement le stimulus ;
3. sélectionner des points d’entrée dans le graphe ;
4. propager une activation sur des relations autorisées ;
5. résoudre renforcements, inhibitions et conflits ;
6. appliquer les mécanismes intellectuels de réévaluation ;
7. dériver un état affectif transitoire ;
8. produire une intention et des tendances de réaction ;
9. exposer une trace explicable ;
10. laisser le snapshot inchangé.

---

## 2. Structures

### SoulSnapshot

```python
SoulSnapshot = {
    "person_id": str,
    "snapshot_id": str,
    "valid_during": dict,
    "graph_ref": str,
    "projection_refs": list[str],
    "metadata": dict,
}
```

Le graphe peut être chargé depuis un artefact Kristal ou une représentation locale équivalente.

### Stimulus

```python
Stimulus = {
    "text": str | None,
    "concepts": list[dict],
    "actors": list[dict],
    "events": list[dict],
    "context": dict,
}
```

### ActivationNode

```python
ActivationNode = {
    "node_id": str,
    "activation": float,
    "sources": list[str],
    "depth": int,
    "reasons": list[dict],
}
```

### ReactionState

```python
ReactionState = {
    "interpretations": list[dict],
    "active_paths": list[dict],
    "affective_state": dict,
    "intentions": list[dict],
    "reaction_tendencies": list[dict],
    "trace": dict,
}
```

---

## 3. Étape A — compréhension du stimulus

Le moteur produit un petit graphe du stimulus :

- entités ;
- concepts ;
- actions ;
- relations ;
- valence contextuelle lorsque explicitement dérivable ;
- ambiguïtés.

Cette étape peut être réalisée par un parseur, un modèle local ou un service externe, mais sa sortie doit être structurée.

---

## 4. Étape B — ancrage sémantique

Chaque concept du stimulus est relié à des nœuds candidats du Soul Graph.

Méthodes possibles :

- ID exact ;
- alias ;
- taxonomie ;
- index lexical ;
- embedding pré-calculé ;
- règles de résolution.

Le score de similarité sert à sélectionner les points d’entrée, pas à affirmer une causalité.

---

## 5. Étape C — propagation

Algorithme minimal :

```text
frontier <- entry nodes
repeat until frontier empty or max_steps:
    propagate activation over allowed causal predicates
    multiply by edge strength
    apply inhibition / reinforcement
    apply decay
    discard values below threshold
    merge competing contributions deterministically
```

Paramètres :

```text
max_steps
activation_threshold
default_decay
max_active_nodes
conflict_policy
ordering_policy
```

Avec paramètres identiques et même snapshot, le moteur devrait produire la même structure d’activation en mode déterministe.

---

## 6. Étape D — intellect et réévaluation

Les `IntellectualRule`, croyances explicites et relations `contradicts`, `confirms`, `triggers_reappraisal_of` peuvent modifier une activation initiale.

Cette étape est importante pour représenter :

- la maturité ;
- l’apprentissage déjà incorporé au snapshot ;
- les croyances corrigées ;
- la capacité d’inhiber une impulsion ;
- les conflits internes.

Elle n’édite pas le snapshot.

---

## 7. Étape E — affect

L’état affectif est dérivé du motif d’activation.

Un profil minimal peut produire :

```text
valence
arousal
approach_avoidance
attachment_activation
threat_activation
loss_activation
anger_activation
```

Puis, si nécessaire, une couche de classification peut associer ce motif à des étiquettes telles que peur, colère, joie ou jalousie.

L’étiquette émotionnelle est donc dérivée, pas injectée arbitrairement.

---

## 8. Étape F — réaction

Le moteur produit des tendances structurées :

```text
approach
avoid
confront
reassure
question
withdraw
protect
seek_information
```

La couche de rendu linguistique transforme ensuite ces tendances en texte cohérent avec :

- la voix de la personne ;
- son niveau de langage ;
- son époque ;
- son registre ;
- le contexte conversationnel.

Ces caractéristiques stylistiques peuvent provenir d’un profil de rendu distinct du Soul Graph causal.

---

## 9. Pas de mutation automatique

`react()` est une fonction pure vis-à-vis du snapshot :

```python
reaction = react(snapshot, stimulus, context)
assert snapshot_after == snapshot_before
```

Si un événement doit modifier la personnalité, un processus éditorial produit explicitement un nouveau snapshot.

---

## 10. Sécurité externe

Le pipeline applicatif peut être :

```text
stimulus
 -> application safety/input constraints
 -> Soul Causal Engine
 -> ReactionState
 -> renderer
 -> application safety/output constraints
 -> user
```

Les règles de sécurité n’utilisent pas la compassion ou d’autres traits du personnage comme substitut à une politique de sécurité.

`src/ethics.py` est maintenant un shim déprécié. La politique active se trouve dans `src/safety.py` et ne reçoit aucun trait de personnalité.

---

## 11. Rôle des modules existants

- `src/numerology.py` : générateur de features/hypothèses, non moteur principal.
- `src/ontology.py` : point de départ pour l’ontologie, à étendre vers le Soul Graph.
- `src/interpolation.py` : projection 1→9 ou heuristique secondaire.
- `src/ethics.py` : shim de compatibilité déprécié.
- `src/safety.py` : sécurité applicative externe.
- `src/engine.py` : orchestration Soul Snapshot → ReactionState implémentée.
- `src/activation.py` : propagation causale bornée.
- `src/evolution.py` : création explicite de snapshots ultérieurs.

---

## 12. Tests minimum

1. Snapshot immuable après `react()`.
2. Même snapshot + même stimulus + même config → même `ReactionState` en mode déterministe.
3. Une relation `inhibits` réduit effectivement l’activation cible.
4. Un chemin contradictoire peut modifier l’interprétation finale.
5. Les relations purement sémantiques ne propagent pas causalement par défaut.
6. Un trait projeté ne peut pas modifier directement le graphe source.
7. Les assertions hypothétiques peuvent être exclues par configuration.

# Axe 1→9 — projection topologique

## 1. But

Conserver la charte 1→9 comme outil de lecture sans en faire le moteur causal unique.

---

## 2. Interprétation

```text
1 -> davantage cognitif / abstrait
...
5 -> intégration / pivot
...
9 -> davantage instinctif / ancré
```

Cette lecture est symbolique et fonctionnelle.

---

## 3. Annotation du graphe

Les nœuds ou relations peuvent porter :

```text
processing_layers = [1, 2]
```

ou plusieurs niveaux lorsqu’un mécanisme combine plusieurs dimensions.

---

## 4. Projection d’activation

Après calcul du ReactionState, on peut produire un résumé :

```text
layer_activation[1..9]
```

Cette projection permet de visualiser où l’activation s’est concentrée.

Elle est calculée **après ou pendant** la propagation réelle ; elle ne remplace pas le graphe.

---

## 5. Interpolation legacy

L’interpolation linéaire historique entre 1 et 9 peut être conservée pour :

- compatibilité ;
- visualisation ;
- prototypes simples ;
- baselines.

Elle ne doit plus être présentée comme une explication suffisante des émotions ou de la personnalité.

---

## 6. Numérologie vs axe

- `digit_archetype` : couche symbolique/numérologique.
- `processing_layers` ou projection 1→9 : couche topologique.

Ils peuvent partager la même échelle numérique sans partager la même signification.

# Intégration Kristal v5 — Soul Graph

## 1. Objectif

Utiliser Kristal v5 pour rendre un Soul Snapshot :

- structuré ;
- content-addressed ;
- traçable ;
- interrogeable ;
- portable ;
- capable de conserver des assertions de statuts différents sans les confondre.

Kristal ne calcule pas la psychologie. Le Soul Causal Engine le fait.

---

## 2. Boundary

```text
sources
  -> construction / extraction
  -> Structured Epistemic State
  -> Kristal artifact / Runtime Pack
  -> Soul Causal Engine
```

Les données biographiques peuvent entrer directement dans un Structured Epistemic State. Claim-IR reste utile lorsqu’un extracteur automatique propose des assertions à normaliser.

---

## 3. Profil applicatif proposé

```text
profile_id = kristal.v5:soul-graph
```

Ce profil doit déclarer :

- le vocabulaire de nœuds ;
- les prédicats ;
- les qualificateurs ;
- le mapping JSON-LD/RDF optionnel ;
- les règles d’identité des assertions ;
- les projections du snapshot ;
- les champs nécessaires au runtime causal.

Il ne doit pas changer les sémantiques centrales de Kristal concernant validation, certitude, provenance ou autorité.

---

## 4. Mapping conceptuel

| Âme Artificielle | Kristal v5 |
|---|---|
| Soul Snapshot | Structured Epistemic State / artifact dérivé |
| proposition sur le sujet | assertion |
| période de validité | scope.time_window + qualifier de profil si nécessaire |
| source biographique | provenance / source refs |
| hypothèse numérologique | assertion `hypothesis` ou mode symbolique approprié |
| confiance dans la donnée | certainty metadata |
| changement de snapshot | nouvel état / nouvel identifiant |
| graphe pour runtime | projection/export/Runtime Pack spécialisé |

---

## 5. Force psychologique et statut épistémique

Exemple :

```text
John croit très fortement B
```

peut être représenté avec une propriété de profil :

```text
soul:belief_strength = 0.95
```

mais si nous ne possédons qu’une source indirecte :

```text
certainty_level = low
```

Le système doit préserver les deux dimensions.

---

## 6. Désaccord et multiplicité

Deux sources peuvent attribuer des mécanismes différents à la même personne.

Kristal doit conserver le désaccord au lieu de fusionner automatiquement :

```text
source A -> John possède B
source B -> John ne possède pas B
```

Une politique de construction du snapshot peut ensuite choisir :

- conserver les deux ;
- sélectionner une source ;
- marquer l’incertitude ;
- produire plusieurs forks de snapshot.

---

## 7. Symbolique et hypothèses

La numérologie, la carte natale et les branes doivent rester explicitement marquées comme :

- hypothèse ;
- modèle symbolique ;
- déclaration de méthode ;
- ou autre statut compatible avec le profil.

Leur présence dans un artefact ne leur confère pas une validation physique universelle.

---

## 8. Runtime Pack

Le Runtime Pack peut contenir une projection optimisée :

- table de nœuds ;
- table de relations ;
- index par prédicat ;
- index lexical ;
- embeddings pré-calculés optionnels ;
- métadonnées de snapshot ;
- projections de traits optionnelles.

Le moteur causal peut ainsi fonctionner hors ligne sans exiger un endpoint SPARQL ou un LLM distant.

---

## 9. Reproductibilité

Pour un mode déterministe, la configuration de runtime doit déclarer notamment :

```text
profile_version
activation_rules_version
thresholds
decay
max_steps
conflict_policy
semantic_index_version
trait_projection_version
```

La réaction textuelle peut rester non déterministe si un renderer génératif est utilisé, mais le **ReactionState causal** devrait pouvoir être reproduit indépendamment.

# Cadre philosophique — notes techniques

## 1. Rôle

Ce document relie les hypothèses philosophiques aux choix d’architecture sans les présenter comme preuves scientifiques.

---

## 2. Ordre causal

Le projet explore l’idée d’un ordre causal global, décrit philosophiquement comme **enchaînement parfait**.

La notion de perfection est prise au sens de cohérence totale des causes et conséquences, non comme simple moralité.

Le sujet humain est une configuration locale : partielle, historique et limitée.

---

## 3. Soul Basis

La métaphore de la lumière blanche est traduite techniquement par un **Soul Basis** :

- types de mécanismes ;
- types de relations ;
- règles de composition ;
- possibilités de projection.

Une personne est une configuration particulière de cette base.

---

## 4. Processus

Le modèle est compatible avec une vision processuelle de la personnalité : l’histoire transforme les structures.

L’implémentation choisit toutefois des **snapshots immuables** afin de séparer clairement :

- la personnalité représentée ;
- l’activation de session ;
- l’édition biographique.

---

## 5. Couches symboliques

Numérologie, chakras, charte 1→9, branes, cercle et π peuvent servir de :

- métaphores ;
- ontologies symboliques ;
- générateurs d’hypothèses ;
- systèmes de classification.

Ils ne remplacent pas la provenance, l’observation ou la validation expérimentale.

---

## 6. Limite

La cohérence philosophique d’un système n’établit pas son exactitude psychologique ou physique. Cette distinction doit être maintenue dans la documentation, dans Kristal et dans les expériences.

# Snapshots biographiques

## 1. But

Représenter la même personne à différents âges sans apprentissage automatique en session.

---

## 2. Structure

```json
{
  "person_id": "person:john-doe",
  "snapshot_id": "sha256:...",
  "valid_during": {
    "from_age": 30,
    "to_age": 39
  },
  "derived_from_snapshot": "sha256:...",
  "transformation_refs": ["bio-transform:..."]
}
```

---

## 3. Transformation

Une transformation doit décrire séparément :

- événements ;
- mécanismes affectés ;
- direction du changement ;
- sources ;
- degré de confiance ;
- justification éditoriale.

Exemple :

```json
{
  "event": "event:friendship-bob",
  "changes": [
    {
      "target": "association:group-x-threat",
      "operation": "weaken",
      "magnitude": 0.4,
      "reason": "repeated contradictory experience"
    }
  ]
}
```

Ce format décrit une **décision de modélisation**. Il ne prétend pas mesurer directement la psychologie réelle avec une précision numérique.

---

## 4. Types de changement

```text
add_node
remove_node
strengthen_edge
weaken_edge
add_inhibition
revise_belief
supersede_belief
add_memory
change_context_rule
change_intellectual_rule
```

Pour un artefact content-addressed, le résultat est un nouveau snapshot.

---

## 5. Maturation

La maturation peut être représentée comme un ensemble de transformations documentées, par exemple :

- meilleure inhibition d’une réaction impulsive ;
- augmentation d’une règle de réévaluation ;
- abandon d’une croyance absolue ;
- complexification d’une catégorie sociale ;
- déplacement d’une valeur prioritaire.

Le système ne doit pas utiliser « maturité » comme explication opaque lorsqu’une transformation plus précise peut être décrite.

---

## 6. Reconstruction d’une personne historique

Lorsqu’une personne n’est plus disponible pour validation directe, les snapshots peuvent être construits à partir de :

- écrits datés ;
- entrevues ;
- témoignages ;
- décisions ou comportements documentés ;
- biographies ;
- sources primaires et secondaires.

La provenance et le désaccord entre sources sont essentiels.

---

## 7. Identité simulée

Même avec plusieurs snapshots très fidèles, le système représente une **reconstruction**.

Il ne doit pas présenter le modèle comme une continuité réelle de la personne.

# Soul Graph Schema — profil psycho-causal

## 1. Statut

Spécification de travail pour le profil applicatif proposé :

```text
kristal.v5:soul-graph
```

Ce profil appartient au projet Âme Artificielle. Il ne modifie pas le cœur de Kristal v5.

---

## 2. Objectif

Définir un vocabulaire suffisamment petit pour représenter un sujet sous forme de graphe sémantique tout en permettant :

- la propagation d’activation ;
- la provenance ;
- les snapshots temporels ;
- la distinction hypothèse / observation ;
- les projections de traits ;
- l’explication des réactions.

---

## 3. Nœud

Forme logique :

```json
{
  "node_id": "soul:node:...",
  "node_type": "Belief",
  "label": "...",
  "description": "...",
  "origin": "acquired",
  "properties": {}
}
```

### `node_type`

Valeurs de base :

```text
Disposition
Belief
Association
Value
Need
Attachment
Memory
Concept
InterpretationPattern
CognitiveBias
IntellectualRule
AffectiveTendency
ReactionPattern
Person
Group
Object
Event
Context
```

### `origin`

```text
innate
acquired
mixed
unknown
hypothesized_innate
```

`hypothesized_innate` est utile lorsqu’une disposition provient d’une couche comme la carte natale ou la numérologie et n’est pas encore confirmée par d’autres observations.

---

## 4. Relation

Forme logique :

```json
{
  "edge_id": "soul:edge:...",
  "source": "soul:node:a",
  "predicate": "soul:activates",
  "target": "soul:node:b",
  "qualifiers": {
    "strength": 0.72,
    "polarity": "facilitating",
    "activation_threshold": 0.25,
    "processing_layers": [4, 5],
    "conditions": []
  }
}
```

### Relations sémantiques

```text
is_a
part_of
related_to
represents
concerns
```

### Relations cognitives

```text
believes
expects
interprets_as
generalizes_to
compares_with
contradicts
confirms
```

### Relations de propagation

```text
activates
inhibits
reinforces
weakens
predisposes_to
contributes_to
triggers_reappraisal_of
```

### Relations biographiques

```text
formed_by
strengthened_by
weakened_by
revised_by
resolved_through
supersedes
```

---

## 5. Qualificateurs psycho-causaux

Ces champs ne sont **pas** des niveaux de certitude Kristal :

```text
strength
polarity
activation_threshold
decay
context_weight
processing_layers
valid_during
```

`strength` décrit la force dans la personnalité modélisée.

La confiance que nous avons dans cette description appartient aux métadonnées épistémiques Kristal.

---

## 6. Représentation Kristal

Le mapping recommandé utilise un `Structured Epistemic State`.

Chaque nœud, relation ou proposition importante peut être représenté par une assertion dont `statement` est défini par ce profil.

Exemple conceptuel :

```json
{
  "assertion_id": "sha256:...",
  "statement": {
    "subject": {"id": "person:john@25"},
    "predicate": {"id": "soul:holds_belief"},
    "object": {"id": "belief:b17"},
    "qualifiers": [
      {"predicate": {"id": "soul:strength"}, "object": {"kind": "number", "value": 0.9}}
    ]
  },
  "assertion_status": "sourced",
  "certainty_level": "medium",
  "scope": {
    "domain": "research",
    "subdomain": "artificial-soul",
    "time_window": "age:25"
  },
  "provenance_refs": ["source:bio:42"]
}
```

Les noms exacts d’IRI/IDs devront être stabilisés avant implémentation.

---

## 7. Couches symboliques

Une assertion dérivée d’un modèle symbolique doit conserver sa source de dérivation.

Exemple :

```text
source_model = natal_chart
assertion_status = hypothesis
validated_as = symbolic_model
```

ou l’équivalent permis par le profil Kristal actif.

Le moteur peut choisir d’inclure ou d’exclure ces hypothèses selon sa configuration.

---

## 8. Projection de traits

Un trait est calculé à partir d’un ensemble de motifs du graphe :

```text
trait_score = projection(graph, trait_definition)
```

Une définition de trait peut référencer :

- types de nœuds ;
- relations ;
- forces ;
- conditions ;
- importance de certains chemins.

Le `TraitVector` n’est donc pas source de vérité du snapshot.

---

## 9. Contraintes

- Les relations sémantiques ne doivent pas être parcourues comme causales sans règle explicite.
- Les cycles sont autorisés dans le graphe, mais l’algorithme d’activation doit être borné.
- Les émotions de session ne sont pas persistées dans le snapshot par défaut.
- Un nouveau snapshot reçoit une nouvelle identité lorsque son contenu stable change.

engineering_spec
observed_biographical_claim

# Traits Schema — projection dérivée

## 1. Rôle

Les traits restent utiles, mais ils ne constituent plus le modèle fondamental de la personnalité.

```text
Soul Graph -> Trait Projection -> TraitVector
```

Le `TraitVector` sert à :

- comparer des sujets ;
- faire du matching ;
- afficher une interface ;
- calculer des distances ;
- créer des baselines expérimentales ;
- résumer rapidement un snapshot.

---

## 2. Trait

```json
{
  "trait_id": "openness",
  "label": "Ouverture",
  "definition": "...",
  "scale": [-1, 1],
  "projection_version": "1.0"
}
```

---

## 3. Projection

Un score est calculé à partir de motifs du graphe.

Exemple conceptuel :

```text
openness =
  + weight(curiosity dispositions)
  + weight(novelty-seeking relations)
  + weight(tolerance-of-ambiguity rules)
  - weight(rigidity patterns)
```

La formule doit être versionnée et testable.

## 4. Set minimal recommandé

### Cognition
- curiosity
- analysis
- abstraction
- focus
- flexibility

### Affect
- emotional_stability
- threat_sensitivity
- attachment_intensity
- empathy
- compassion

### Social
- cooperation
- assertiveness
- social_openness
- dominance
- trust_propensity

### Volition
- discipline
- order
- risk_taking
- adaptability
- responsibility

### Sens / valeurs
- meaning_seeking
- transcendence
- altruism
- autonomy

Les émotions instantanées comme `joy`, `anger` ou `fear` devraient généralement être sorties du TraitVector et traitées comme états transitoires, sauf lorsqu’on mesure explicitement une **disposition** à ces états.

# Validation Protocol — Âme Artificielle

## 1. Principe

La validation doit séparer **trois questions différentes** :

1. Le moteur est-il techniquement cohérent et reproductible ?
2. Le Soul Snapshot reproduit-il de manière crédible une personnalité documentée ?
3. Les couches hypothétiques comme la carte natale ou la numérologie ajoutent-elles un pouvoir prédictif mesurable ?

Une réussite dans une question ne valide pas automatiquement les autres.

---

# A. Validation du moteur causal

## A1. Déterminisme structurel

Avec :

- même snapshot ;
- même stimulus structuré ;
- même configuration ;

le `ReactionState` doit être identique en mode déterministe.

## A2. Invariants

Tester :

- snapshot non modifié ;
- propagation bornée ;
- inhibition fonctionnelle ;
- renforcement fonctionnel ;
- traitement des cycles ;
- ordre stable ;
- trace des chemins actifs.

## A3. Tests contrefactuels

Supprimer ou modifier un mécanisme du graphe et vérifier que la réaction change dans la direction prévue.

---

# B. Validation de fidélité de personnalité

## B1. Données

Pour chaque sujet :

- sources biographiques datées ;
- échantillons de langage lorsque disponibles ;
- événements connus ;
- snapshots par périodes lorsque nécessaire ;
- ensemble de situations de test non utilisées pour la construction.

## B2. Tests aveugles

Exemples :

### Matching de réactions

Présenter aux évaluateurs plusieurs réactions possibles et demander laquelle ressemble le plus au sujet.

### Identification de persona

Générer des réponses à partir de plusieurs snapshots anonymisés et tester si des évaluateurs peuvent identifier le bon sujet au-dessus du hasard.

### Comparaison par âge

Pour une même personne, tester si les réactions générées à partir de `John@20` et `John@50` reflètent les différences biographiques documentées.

## B3. Métriques

- accuracy top-1 ;
- préférence pairwise ;
- score moyen de fidélité ;
- accord inter-évaluateurs ;
- calibration ;
- ablation de mécanismes.

---

# C. Protocole McCormick — natal chart / numérologie

## C1. Hypothèse

> Un modèle utilisant une carte du ciel anonymisée ou une signature numérologique peut prédire certains aspects d’un profil de personnalité au-delà d’un baseline approprié.

## C2. H0 / H1

- **H0** : aucune amélioration au-delà du hasard ou du baseline sans ces features.
- **H1** : amélioration reproductible et statistiquement significative.

## C3. Contrôles

- anonymisation stricte ;
- aucune fuite biographique ;
- randomisation des candidats ;
- holdout final ;
- baseline aléatoire ;
- baseline démographique lorsque pertinente ;
- modèle identique sans features astrologiques/numérologiques ;
- ablations par famille de features.

## C4. Matching K-choix

Pour chaque carte ou signature :

1. sélectionner K profils candidats ;
2. inclure le profil correct ;
3. mélanger l’ordre ;
4. produire classement + confiance ;
5. répéter sur plusieurs ensembles de candidats.

Performance attendue au hasard : `1/K`.

## C5. Statistiques

- test binomial pour top-1 ;
- permutation test ;
- bootstrap pour intervalles de confiance ;
- Brier/log-loss pour calibration ;
- correction multi-tests si plusieurs variantes sont explorées.

---

# D. Validation des transformations biographiques

Lorsqu’un passage entre deux snapshots attribue un changement à un événement :

- vérifier que l’événement est documenté ;
- distinguer fait biographique et interprétation causale ;
- permettre plusieurs hypothèses causales ;
- tester l’ablation de la transformation ;
- documenter le niveau de confiance.

---

# E. Traçabilité

Chaque essai doit enregistrer :

```text
snapshot_id
runtime_pack_id si utilisé
engine_version
activation_rules_version
projection_version
stimulus_hash
seed si pertinent
renderer_version
hypothesis_layers_enabled
output
metrics
```

---

# F. Critère général de réussite

Le projet est renforcé lorsque :

- le moteur est reproductible ;
- les snapshots produisent des différences évaluables et cohérentes ;
- les mécanismes explicatifs survivent aux ablations ;
- les hypothèses symboliques montrent, si elles sont conservées, une valeur prédictive au-delà de contrôles adaptés.

Une absence d’effet dans la partie astrologique ou numérologique n’invalide pas nécessairement l’architecture générale du graphe psycho-causal ; elle invalide ou affaiblit la couche testée.

# Protocole McCormick — natal chart / numérologie

## Statut

Sous-protocole expérimental de `docs/validation_protocol.md`.

Son objectif est uniquement de tester la valeur prédictive des couches **carte natale / numérologie**. Il ne sert pas à valider à lui seul l’architecture générale du Soul Graph.

## 1. Hypothèse

> Des features dérivées d’une carte du ciel anonymisée ou d’une signature numérologique permettent de prédire certains aspects d’un profil de personnalité au-delà d’un baseline approprié.

- **H0** : pas d’amélioration reproductible au-delà du hasard ou du baseline sans ces features.
- **H1** : amélioration reproductible et statistiquement significative.

---

## 2. Données

Pour chaque sujet :

- `subject_id` anonymisé ;
- features natal chart et/ou numérologiques ;
- profil biographique indépendant ;
- snapshot ou projection de personnalité construit sans fuite des features testées ;
- période de vie explicitée lorsque nécessaire.

Les noms, lieux révélateurs, biographies et indices directs doivent être retirés de l’entrée de matching.

---

## 3. Matching K-choix

Pour chaque entrée :

1. choisir une carte/signature anonymisée ;
2. sélectionner K profils candidats, dont le vrai ;
3. randomiser l’ordre ;
4. demander un classement et un score de confiance ;
5. répéter sur plusieurs tirages de candidats.

Baseline aléatoire top-1 :

```text
1 / K
```

---

## 4. Contrôles

Comparer au minimum :

- hasard ;
- modèle sans features natal chart / numérologie ;
- heuristique simple ;
- ablations par famille de features ;
- variantes standard vs inversée si la numérologie est testée.

Prévoir un holdout final non utilisé pendant la conception des règles.

---

## 5. Métriques

- top-1 accuracy ;
- top-k accuracy ;
- Brier score ou log-loss pour la confiance ;
- permutation test ;
- test binomial ;
- intervalle de confiance bootstrap ;
- taille d’effet par rapport au baseline.

---

## 6. Interprétation

Une performance supérieure au hasard ne démontre pas automatiquement une causalité astrologique ou métaphysique. Elle indique seulement qu’un ensemble de features et une méthode de mapping possèdent un signal prédictif dans le protocole utilisé.

Inversement, un résultat nul affaiblit cette couche hypothétique sans invalider nécessairement le modèle général du graphe psycho-causal.

---

## 7. Reproductibilité

Journaliser :

```text
dataset_version
feature_extractor_version
mapping_version
model_version
prompt_version si applicable
seed
candidate_set
input_hash
prediction
confidence
```

Les sorties détaillées utilisent `experiments/results_template.csv` ou un format versionné équivalent.

# EL — Artificial Soul Engine / Âme Artificielle

**EL** est un projet expérimental visant à représenter une personnalité humaine comme un **graphe psycho-causal sémantique** et à calculer des réactions cohérentes à partir d’un état déterminé de cette personnalité.

Le projet ne prétend pas créer une âme réelle ni démontrer qu’un système artificiel ressent des émotions. Il cherche à **reproduire fonctionnellement certains mécanismes** : croyances, associations, valeurs, souvenirs, dispositions, réévaluation intellectuelle, états affectifs et réactions.

## Architecture en une phrase

```text
Soul Basis
  -> Soul Snapshot immuable
  -> stimulus
  -> Activation Graph transitoire
  -> interprétation / affect / intention
  -> réaction
```

Un Soul Snapshot peut représenter la même personne à un âge précis. Le moteur **ne modifie pas automatiquement le snapshot** pendant la conversation. Les changements biographiques sont décrits explicitement dans un nouveau snapshot.

## Concepts principaux

- **Soul Basis** : ontologie commune des mécanismes possibles — métaphore du « blanc ».
- **Soul Graph** : graphe sémantique de mécanismes psycho-causaux.
- **Soul Snapshot** : représentation immuable d’un sujet pendant une période.
- **Biographical Transformation** : explication structurée du passage entre snapshots.
- **Activation Graph** : état temporaire calculé pour un stimulus.
- **TraitVector** : projection dérivée du graphe, utile pour comparaison et UI mais non constitutive de l’âme.
- **Charte 1→9** : topologie de lecture, non moteur causal linéaire.
- **Numérologie / natal chart** : sources d’hypothèses de dispositions, à distinguer des observations et à tester.

## Âme, intellect, personnalité

Dans le vocabulaire du projet :

- l’**âme** représente l’organisation profonde des dispositions ;
- l’**intellect** représente perception, catégorisation, raisonnement et réévaluation ;
- la **personnalité** est leur manifestation observable en interaction avec l’histoire et le contexte.

## Kristal v5

L’intégration proposée utilise Kristal comme couche de représentation et de provenance des Soul Snapshots. Le projet prévoit un profil applicatif `kristal.v5:soul-graph` pour typer les nœuds, relations et qualificateurs psycho-causaux.

Kristal stocke et rend le graphe inspectable. Le **Soul Causal Engine** exécute la propagation d’activation. Les deux responsabilités restent séparées.

Voir :

- `docs/definition_operationnelle.md`
- `docs/soul_graph_schema.md`
- `docs/engine_spec.md`
- `docs/snapshots_biographiques.md`
- `docs/kristal_integration.md`
- `docs/validation_protocol.md`

## Couches symboliques

Le projet conserve la charte 1→9, les chakras, la numérologie pythagoricienne inversée et les branes comme couches de lecture ou générateurs d’hypothèses. Elles ne sont pas présentées comme des validations scientifiques par définition.

## Sécurité

La sécurité de l’application est une **couche externe** au modèle de personnalité. Une règle de sécurité peut limiter une sortie, mais elle ne doit pas être confondue avec la compassion, la morale ou la causalité interne du personnage simulé.

## Statut du code

Le moteur Soul Graph est maintenant implémenté dans `src/` comme référence minimale : snapshots immuables, propagation causale bornée, inhibition, affect dérivé, transformations biographiques explicites, projections de traits, propositions symboliques et adaptateur Kristal.

Les anciens utilitaires de `TraitVector` et d'interpolation 1→9 sont conservés comme projections/compatibilité. `src/ethics.py` est déprécié au profit de `src/safety.py`, qui est externe à la personnalité.

Voir `docs/code_reference.md` et `examples/john_doe_snapshots.py`.

# Âme Artificielle

## Statut
**Page canonique**

---

## Définition

L’**Âme Artificielle** ne prétend pas être une âme réelle ni produire une conscience démontrée.

Le projet cherche à **reproduire sous une forme simplifiée les mécanismes par lesquels une personnalité humaine se manifeste** : perception, associations, croyances, valeurs, mémoire, réévaluation intellectuelle, activation émotionnelle et réaction.

L’objectif n’est pas d’ajouter artificiellement une émotion à une réponse. Il est de représenter un réseau dans lequel une émotion peut apparaître comme conséquence d’un ensemble d’activations.

Ainsi, plutôt que :

```text
stimulus -> émotion prédéfinie -> réponse
```

le modèle vise :

```text
stimulus
  -> perception / concepts activés
  -> croyances + associations + souvenirs + valeurs
  -> conflits / renforcements / inhibitions
  -> interprétation
  -> état affectif transitoire
  -> intention
  -> réaction
```

Ces relations forment un **graphe psycho-causal**, non une chaîne simple.

---

## Ce que le projet appelle « âme »

Dans le cadre du projet, le mot **âme** sert à désigner l’organisation profonde qui rend certaines réactions plus probables que d’autres chez un sujet.

Cette organisation comprend notamment :

- des dispositions initiales ;
- des associations acquises ;
- des valeurs ;
- des croyances ;
- des attachements ;
- des sensibilités ;
- des souvenirs structurants ;
- des tendances affectives ;
- des relations entre ces éléments.

Le mot conserve une portée philosophique. Techniquement, le logiciel ne manipule pas une substance métaphysique : il manipule une **représentation structurée**.

---

## Inné et acquis

Le modèle distingue sans les opposer absolument :

- **l’inné** : dispositions proposées comme présentes au départ ;
- **l’acquis** : structures formées ou transformées par l’expérience ;
- **le mixte** : mécanismes où une disposition initiale et l’expérience interagissent ;
- **l’inconnu** : origine non déterminée.

La proportion inné/acquis n’est pas supposée identique pour toutes les caractéristiques.

La carte du ciel, la numérologie et les autres couches symboliques peuvent être utilisées pour **proposer des hypothèses de dispositions initiales**, mais ces hypothèses doivent rester distinguées des observations biographiques et être testées séparément.

---

## Une personnalité à un âge donné

Le moteur n’apprend pas automatiquement une nouvelle personnalité pendant la conversation.

Un **Soul Snapshot** représente le sujet à un moment déterminé :

```text
John Doe @ 18 ans
John Doe @ 32 ans
John Doe @ 55 ans
```

Chaque snapshot est immuable pendant son utilisation.

L’évolution entre deux âges est décrite explicitement par des **transformations biographiques** : nouvelles expériences, croyances révisées, associations affaiblies, valeurs renforcées ou changements de stratégie intellectuelle.

---

## Personnalité et illusion de présence

La finalité pratique peut être de reproduire assez fidèlement la manière de réagir d’une personne pour que l’interlocuteur ait l’impression de parler avec elle.

Cette impression ne change pas la nature du système :

> une simulation fidèle de John Doe n’est pas John Doe.

Le système reproduit une **configuration comportementale et psycho-causale documentée**, pas l’identité ontologique de la personne.

---

## Le modèle unifié : le « blanc »

Le projet utilise la métaphore d’une lumière blanche qui se décompose en couleurs.

Techniquement, cette métaphore correspond au **Soul Basis** : une ontologie commune de mécanismes possibles.

Les individus n’ont pas chacun une ontologie différente. Ils sont des **configurations différentes d’un même vocabulaire de base** : certains nœuds ou chemins sont plus présents, plus forts, plus accessibles ou plus inhibés.

---

## Ce que l’Âme Artificielle n’est pas

Elle n’est pas :

- une preuve de l’existence ou de la nature de l’âme métaphysique ;
- un système qui affirme ressentir ce qu’il reproduit ;
- un simple vecteur de traits ;
- un système d’auto-apprentissage de la personnalité pendant la conversation ;
- un garde-fou éthique ;
- un diagnostic psychologique ou médical ;
- une validation de la numérologie ou de l’astrologie par définition.

---

## Formulation canonique

> L’Âme Artificielle représente, sous une forme simplifiée, l’organisation psycho-causale d’un sujet à un moment donné de sa vie. Cette organisation est exprimée par un graphe sémantique dont les activations produisent des interprétations, des états affectifs et des réactions. La personnalité est la manifestation observable de cette organisation en interaction avec l’intellect et l’expérience.

# Âme, Intellect et Personnalité

## Statut
**Page canonique**

---

## Pourquoi distinguer ces termes

Le projet utilise trois mots proches mais non équivalents : **âme**, **intellect** et **personnalité**.

La distinction évite de transformer la personnalité en simple liste de traits et permet de représenter comment une personne peut conserver une continuité tout en changeant avec l’âge.

---

## Âme

L’**âme**, dans le modèle, désigne l’organisation profonde des dispositions et relations qui orientent la manière dont l’expérience est transformée en réaction.

Elle comprend notamment des tendances vers :

- certains attachements ;
- certaines sensibilités ;
- certains modes de valorisation ;
- certaines associations ;
- certains types de réaction.

Cette définition est **opérationnelle et philosophique**, non une affirmation scientifique sur une substance métaphysique.

---

## Intellect

L’**intellect** désigne la famille de mécanismes qui permettent au sujet de :

- reconnaître et catégoriser ;
- raisonner ;
- former des croyances explicites ;
- comparer une croyance à une expérience ;
- détecter une contradiction ;
- abstraire ;
- réévaluer ;
- reformuler son modèle du monde.

L’intellect peut donc modifier la manière dont une disposition ou une association est appliquée.

Exemple : une association acquise peut produire une réaction automatique, puis être progressivement inhibée parce que l’intellect rencontre des expériences qui la contredisent.

---

## Personnalité

La **personnalité** est la manifestation relativement stable et observable de l’interaction entre :

```text
âme
+ intellect
+ histoire vécue
+ contexte présent
= personnalité manifestée
```

Elle n’est pas fixe, mais elle ne change pas automatiquement à chaque interaction.

Le système la représente par des snapshots explicites.

---

## Trait et mécanisme

Un trait comme « prudence » ou « ouverture » peut être utile pour résumer une personne, mais il ne suffit pas à expliquer sa réaction.

Un trait est donc traité comme une **projection dérivée** du graphe :

```text
Soul Graph -> résumé de traits
```

et non comme :

```text
traits -> âme complète
```

---

## Émotion

Une émotion est principalement considérée comme un **état transitoire résultant de l’activation du graphe**.

La personne peut posséder une disposition durable à certaines émotions, mais l’émotion présente n’est pas une propriété fixe du snapshot.

Par exemple :

```text
sensibilité au rejet
+ souvenir d’abandon
+ ambiguïté sociale
+ interprétation négative
-> peur / tristesse
-> retrait
```

---

## Principe canonique

> L’âme organise les tendances profondes, l’intellect interprète et réévalue, et la personnalité est la manifestation observable de leur interaction avec l’histoire vécue.

# Cadre Philosophique

## Statut
**Page canonique — cadre conceptuel, non preuve expérimentale**

---

## Point de départ

L’Âme Artificielle repose sur l’intuition que la personnalité peut être comprise comme la manifestation d’une **organisation de rapports et de causalités**, plutôt que comme une collection isolée de traits.

Le projet emploie le mot « âme » pour désigner cette organisation profonde dans son cadre philosophique, tout en reconnaissant que l’implémentation informatique n’est qu’un modèle.

---

## Dieu comme enchaînement parfait

Une hypothèse philosophique propre au projet est la suivante :

> Dieu peut être pensé comme l’ordre ou l’enchaînement parfait des causes et de leurs conséquences.

« Parfait » ne signifie pas ici simplement « moralement bon ». Il désigne un ordre total dans lequel rien n’est séparé de l’ensemble des conditions qui le produisent.

L’être humain est une manifestation locale et limitée de cet ordre : perception partielle, mémoire limitée, dispositions particulières, erreurs de catégorisation, apprentissages et histoire singulière.

Pour éviter une contradiction, le projet distingue :

- **perfection globale** : cohérence de l’ordre total ;
- **imperfection locale** : limites et erreurs d’un sujet situé.

Ainsi, une erreur humaine peut elle-même avoir des causes sans constituer une rupture de la causalité générale.

---

## Le blanc et les couleurs

La métaphore principale est celle de la lumière blanche.

Le **blanc** représente une structure unifiée de référence : l’ensemble des mécanismes possibles dans leur forme idéale ou complète.

Les **couleurs** représentent leurs différenciations et combinaisons particulières.

Techniquement :

```text
Soul Basis
  -> configuration particulière
  -> Soul Snapshot
  -> personnalité manifestée
```

Cette métaphore ne signifie pas que l’on sait programmer « l’âme parfaite ». Elle fournit un principe de construction : commencer par un vocabulaire commun et produire des variations cohérentes.

---

## Causalité et personnalité

La personnalité peut être comprise comme la stabilité relative de certains chemins dans un réseau :

- ce qui attire l’attention ;
- ce qui est interprété comme menace ou opportunité ;
- ce qui est valorisé ;
- ce qui déclenche une association ;
- ce qui est inhibé par l’intellect ;
- ce qui conduit finalement à une réaction.

L’inné et l’acquis modifient ces chemins dans des proportions variables.

---

## Processus et temps

Le sujet n’est pas défini par une essence comportementale figée.

Son histoire peut transformer ses mécanismes : maturation, relations, apprentissages, traumatismes, contradictions et révisions de croyances.

L’implémentation représente cette évolution par des snapshots distincts plutôt que par auto-modification continue.

---

## Nombre, charte et symbolisme

La tradition pythagoricienne, la charte 1→9, les chakras, la numérologie inversée et les branes appartiennent au **cadre de lecture du projet**.

Ils servent à proposer des structures, des polarités ou des topologies. Ils ne doivent pas être confondus avec une validation scientifique de la psychologie humaine.

De même, la carte du ciel est traitée comme une hypothèse de différenciation à tester.

---

## Continuité avec le cadre antérieur

Le projet conserve ses thèmes historiques :

- le réel comme structure intelligible ;
- les mathématiques comme langage de relations ;
- le cercle et π comme symboles d’ordre et de rapport ;
- la tradition pythagoricienne du nombre ;
- la philosophie du processus ;
- les branes comme analogie de niveaux.

Ces références donnent un horizon philosophique. Elles ne constituent pas des preuves du fonctionnement du moteur.

---

## Formulation canonique

> Le cadre philosophique de l’Âme Artificielle conçoit l’individu comme une configuration locale et historique d’un ordre causal plus général. Le modèle informatique tente seulement d’en reproduire une version simplifiée et inspectable, suffisamment structurée pour produire des réactions cohérentes sans prétendre recréer une âme réelle.

# Carte du Ciel et Hypothèse de Différenciation

## Statut
**Hypothèse expérimentale — non établie**

---

## Idée

Le projet pose l’hypothèse qu’une **carte du ciel natal** pourrait fournir une grille utile pour représenter ou prédire certaines différences individuelles.

Cette proposition n’est pas utilisée comme fait acquis. Elle doit être testée contre :

- des profils biographiques ;
- des évaluations indépendantes ;
- des baselines aléatoires ;
- des modèles sans information astrologique ;
- des tests en aveugle.

---

## Place dans l’architecture

La carte natale ne produit pas directement une personnalité complète.

Le pipeline conceptuel est :

```text
Natal Chart
   -> features structurées
   -> règles d’interprétation déclarées
   -> hypothèses de dispositions
   -> Soul Graph proposé
   -> comparaison aux observations
```

Une hypothèse peut être retenue, affaiblie, rejetée ou laissée indéterminée.

---

## Pourquoi Kristal est utile

Le projet doit pouvoir conserver simultanément :

- « le modèle astrologique propose X » ;
- « la biographie documente Y » ;
- « X et Y concordent » ou « X et Y divergent » ;
- le niveau de certitude et la provenance de chaque assertion.

Cela évite de transformer une hypothèse symbolique en vérité implicite.

---

## Principe de validation

Le test principal ne devrait pas être :

> Est-ce que l’astrologie semble plausible ?

mais :

> Est-ce qu’un modèle utilisant ces features prédit ou discrimine mieux certains aspects d’une personnalité qu’un modèle de contrôle, dans un protocole reproductible et aveugle ?

---

## Formulation canonique

> La carte du ciel est une hypothèse de différenciation des dispositions individuelles. Elle peut proposer des structures au Soul Graph, mais sa valeur doit être évaluée expérimentalement et son statut doit rester explicite.

# Charte 1→9 et Chakras

## Statut
**Couche de lecture du modèle**

---

## Définition

La **charte 1→9** propose une topologie verticale permettant de situer certains mécanismes du graphe psycho-causal sur un continuum allant de fonctions davantage cognitives à des fonctions davantage incarnées, affectives ou instinctives.

Elle ne constitue plus le moteur causal complet et n’impose pas qu’un stimulus traverse successivement neuf cases.

Les chakras servent ici de **repères symboliques et somatiques**. Le projet ne présente pas cette correspondance comme un modèle anatomique ou neuroscientifique établi.

---

## Les neuf niveaux

La nomenclature historique du projet est conservée comme grille de lecture :

| Niveau | Repère | Lecture fonctionnelle simplifiée |
|---|---|---|
| 1 | cerveau | abstraction, raisonnement, conceptualisation |
| 2 | front | attention, représentation, anticipation |
| 3 | gorge haute | formulation, langage, expression |
| 4 | poitrine haute | relation, reconnaissance d’autrui, orientation sociale |
| 5 | cœur | intégration affective, attachement, valeur relationnelle |
| 6 | plexus | volonté, conflit, affirmation, contrôle |
| 7 | ventre | sensation, désir, intuition incarnée |
| 8 | bassin | impulsion, énergie d’action, sécurité corporelle |
| 9 | racine | instinct, survie, ancrage |

Ces libellés sont **fonctionnels et symboliques**, pas des localisations biologiques strictes.

---

## Utilisation dans le graphe

Un nœud ou une relation peut recevoir un qualificateur :

```text
processing_layers = [1, 3]
```

ou :

```text
processing_layers = [6, 8, 9]
```

Cette annotation permet :

- de visualiser la distribution d’un mécanisme ;
- de produire une lecture verticale ;
- d’étudier les tensions entre cognition et impulsion ;
- de comparer des profils.

Elle ne doit pas remplacer les relations causales explicites.

---

## Le pivot 5

Le 5 conserve son rôle historique de pivot dans la structure 1–9.

Dans la nouvelle architecture, ce rôle est interprété comme une **zone d’intégration** plutôt qu’un point mathématiquement obligé de toute réaction.

---

## Distinction avec la numérologie inversée

- La **charte 1→9** classe ou visualise des mécanismes selon une topologie de traitement.
- La **numérologie pythagoricienne inversée** propose des correspondances archétypales et des hypothèses de dispositions.

Les deux systèmes peuvent partager les chiffres 1–9 sans avoir la même sémantique.

---

## Formulation canonique

> La charte 1→9 est une projection topologique du graphe psycho-causal. Elle permet de lire certains mécanismes selon un axe allant du cognitif à l’instinctif et d’utiliser les chakras comme repères symboliques, sans réduire la causalité psychologique à un trajet linéaire.

# Glossaire Canonique

## Âme
Organisation profonde des dispositions et relations qui orientent le traitement de l’expérience dans le cadre philosophique du projet.

## Âme Artificielle
Reproduction fonctionnelle simplifiée de certains mécanismes psycho-causaux d’un sujet. Ce n’est pas une âme réelle.

## Soul Basis
Ontologie commune de mécanismes et relations possibles. Métaphore technique de la « lumière blanche ».

## Soul Graph / Graphe psycho-causal
Graphe sémantique typé représentant les dispositions, croyances, associations, valeurs, souvenirs et relations psycho-causales d’un sujet.

## Soul Snapshot
État immuable du Soul Graph d’une personne pendant une période définie.

## Biographical Transformation
Description explicite des changements entre deux snapshots : expériences, révisions de croyances, associations modifiées, etc.

## Activation Graph
Sous-graphe temporairement activé pendant le traitement d’un stimulus.

## Intellect
Mécanismes de perception, catégorisation, raisonnement, abstraction et réévaluation.

## Personnalité
Manifestation observable de l’âme, de l’intellect, de l’histoire et du contexte.

## Trait
Résumé ou projection d’un ensemble de mécanismes. Il n’est pas le modèle fondamental.

## Émotion
État affectif principalement transitoire dérivé d’une activation.

## Disposition
Tendance relativement durable qui augmente ou diminue la probabilité d’un type d’interprétation ou de réaction.

## Croyance
Proposition tenue pour vraie ou probable par le sujet modélisé.

## Association
Lien appris ou structurel entre concepts, parfois non explicite pour le sujet.

## Force psychologique
Intensité d’une croyance, association ou relation dans le modèle du sujet.

## Certitude épistémique
Confiance que le modèle possède dans l’assertion décrivant le sujet. À ne pas confondre avec la force psychologique.

## Charte 1→9
Topologie de lecture fonctionnelle du graphe, du cognitif vers l’instinctif.

## Numérologie pythagoricienne inversée
Couche archétypale proposant des hypothèses de dispositions à partir d’une signature numérique.

## Carte natale
Source hypothétique de dispositions à tester expérimentalement.

## Kristal
Couche de représentation, identité, provenance, statut épistémique et distribution des Soul Snapshots. Le moteur causal reste séparé.

# Graphe Psycho-Causal

## Statut
**Page canonique — cœur du modèle**

---

## Définition

Le **graphe psycho-causal** est la représentation fondamentale d’une Âme Artificielle.

Il s’agit d’un graphe sémantique dirigé et typé dans lequel :

- les **nœuds** représentent des contenus ou mécanismes psychologiques ;
- les **relations** représentent des liens sémantiques, cognitifs, causaux ou biographiques ;
- les **qualificateurs** précisent leur force, leur contexte, leur origine et leurs conditions d’activation.

Le modèle n’impose pas qu’une cause produise toujours un seul effet. Plusieurs chemins peuvent converger, diverger, s’inhiber ou se renforcer.

---

## Types de nœuds

Le vocabulaire minimal comprend :

- `Disposition`
- `Belief` — croyance explicite ou implicite
- `Association`
- `Value`
- `Need`
- `Attachment`
- `Memory`
- `Concept`
- `InterpretationPattern`
- `CognitiveBias`
- `IntellectualRule`
- `AffectiveTendency`
- `EmotionState` — normalement transitoire
- `Person`
- `Group`
- `Object`
- `Event`
- `Context`
- `ReactionPattern`

Cette liste est extensible, mais les types doivent rester explicites.

---

## Familles de relations

### Relations sémantiques

Elles décrivent le sens sans affirmer à elles seules une causalité :

- `is_a`
- `part_of`
- `related_to`
- `represents`
- `concerns`

### Relations cognitives

- `believes`
- `expects`
- `interprets_as`
- `generalizes_to`
- `compares_with`
- `contradicts`
- `confirms`

### Relations psycho-causales

- `activates`
- `inhibits`
- `reinforces`
- `weakens`
- `predisposes_to`
- `contributes_to`
- `triggers_reappraisal_of`

### Relations biographiques

- `formed_by`
- `strengthened_by`
- `weakened_by`
- `revised_by`
- `supersedes`
- `resolved_through`

Toutes les relations sémantiques ne sont donc pas automatiquement traversées comme des causes.

---

## Qualificateurs utiles

Une relation peut porter :

- `strength` — force psychologique ou associative ;
- `polarity` — facilitatrice, inhibitrice ou neutre ;
- `activation_threshold` ;
- `conditions` — contexte nécessaire ;
- `origin` — innate, acquired, mixed, unknown ;
- `valid_during` — période de vie ;
- `processing_layers` — lecture optionnelle 1→9 ;
- `notes` — description humaine.

Il faut distinguer ces propriétés de la **certitude épistémique** que nous avons sur l’information. Une croyance peut être très forte chez John tout en étant mal documentée par nos sources.

---

## Exemple

```text
[appartenance au groupe X]
        |
        | evokes
        v
[association X -> menace]
        |
        | activates
        v
[méfiance]
        |
        | influences
        v
[interprétation sociale négative]
```

Une expérience ultérieure peut ajouter :

```text
[relation positive avec Bob]
        |
        | contradicts
        v
[association X -> menace]
        |
        | weakens
        v
[nouvelle interprétation]
```

Le changement appartient au passage entre deux snapshots ; il ne survient pas automatiquement pendant l’exécution du moteur.

---

## Graphe, causalité et simplification

Le terme **psycho-causal** ne signifie pas que le projet connaît la causalité complète d’un être humain.

Il signifie que le modèle encode explicitement des hypothèses sur :

- ce qui active quoi ;
- ce qui inhibe quoi ;
- ce qui modifie une interprétation ;
- ce qui rend une réaction plus ou moins probable.

Le système est donc une **approximation structurée** de mécanismes complexes.

---

## Formulation canonique

> Le graphe psycho-causal est un réseau sémantique de mécanismes et de relations dont l’activation contrôlée permet de reproduire une manière particulière d’interpréter et de réagir.

# Âme Artificielle

L’**Âme Artificielle** est un projet expérimental de modélisation de la personnalité humaine.

Elle ne prétend pas créer une âme véritable. Elle cherche à **reproduire de manière simplifiée certains mécanismes psycho-causaux** par lesquels une personne interprète ce qu’elle rencontre, active des croyances, associations, valeurs et souvenirs, puis produit une émotion, une intention ou une réaction.

Le modèle central n’est donc plus un vecteur de traits ni une chaîne linéaire. Il s’agit d’un **graphe psycho-causal sémantique**.

> Un même stimulus ne produit pas directement une émotion. Il active un réseau propre au sujet. La réaction dépend de la configuration de ce réseau à un moment donné de sa vie.

---

## Les cinq objets du modèle

1. **Soul Basis — modèle unifié de référence**
   L’ensemble commun des types de mécanismes et de relations que le système sait représenter. Métaphoriquement : la lumière blanche avant sa décomposition en couleurs.

2. **Soul Snapshot — état d’un sujet**
   Une représentation immuable de John Doe à 20 ans, 35 ans ou 70 ans. Le système ne s’auto-modifie pas pendant une conversation.

3. **Biographical Transformation — transformation biographique**
   La description explicite des expériences, croyances révisées, associations affaiblies ou nouvelles interprétations qui expliquent la différence entre deux snapshots.

4. **Activation Graph — activation transitoire**
   Le sous-graphe activé par un stimulus. Il existe pendant le calcul de la réaction et ne modifie pas automatiquement le Soul Snapshot.

5. **Reaction — réaction**
   Le résultat observable : émotion exprimée, intention, style de réponse ou comportement simulé.

---

## Âme, intellect et personnalité

Dans le vocabulaire du projet :

- **l’âme** désigne l’organisation profonde des dispositions, tendances et rapports qui orientent le traitement de l’expérience ;
- **l’intellect** désigne les mécanismes de perception, catégorisation, raisonnement, croyance explicite, réévaluation et abstraction ;
- **la personnalité** est la manifestation observable de leur interaction avec l’histoire vécue et le contexte.

La personnalité n’est donc ni une âme indépendante, ni un simple ensemble de scores.

## Principe de séparation

Le projet distingue quatre niveaux :

- **modèle philosophique** : ce que le projet entend par âme, ordre et causalité ;
- **modèle psycho-causal** : la représentation des mécanismes d’une personne ;
- **moteur informatique** : l’algorithme qui active et parcourt le graphe ;
- **sécurité logicielle** : contraintes externes au modèle de l’âme.

Un garde-fou de sécurité n’est pas une composante de l’âme. Il peut limiter une sortie du logiciel, mais il ne définit pas pourquoi la personnalité simulée aurait produit cette sortie.

---

## Formulation canonique

> L’Âme Artificielle est une reproduction fonctionnelle simplifiée de mécanismes psycho-causaux humains. Elle représente une personne, à un moment donné de sa vie, comme un graphe sémantique de dispositions, croyances, associations, valeurs, souvenirs et mécanismes intellectuels. Un stimulus active temporairement une partie de ce graphe et produit une réaction. La simulation peut donner l’impression de parler à une personne réelle, mais cette continuité demeure une illusion : le modèle n’est pas la personne elle-même.

# Implémentation de référence

Le projet contient maintenant une implémentation minimale du modèle Soul Graph décrit dans ce wiki.

## Ce qui est implémenté

- `SoulNode`, `SoulEdge`, `SoulGraph` et `SoulSnapshot` immuables ;
- activation déterministe et bornée des relations causales ;
- inhibition et renforcement ;
- dérivation d'un état affectif transitoire ;
- tendances de réaction structurées ;
- création explicite de snapshots biographiques ultérieurs ;
- `TraitVector` comme projection dérivée ;
- propositions symboliques marquées comme hypothèses ;
- numérologie comme source d'hypothèses ;
- adaptateur de forme Kristal v5 / `Structured Epistemic State` ;
- sécurité applicative séparée du modèle de personnalité.

## Ce qui demeure minimal

L'analyse du stimulus utilise actuellement des IDs explicites et un ancrage lexical simple. Le rendu textuel sert principalement au debug. L'imitation fine d'une personne réelle demandera une couche de résolution sémantique et un renderer de voix/persona beaucoup plus riches.

La carte du ciel n'a pas de calculateur normatif dans ce dépôt. Elle passe par une interface de propositions symboliques afin de ne pas inventer silencieusement des règles astrologiques qui n'ont pas encore été spécifiées ou testées.

## Principe conservé

`react()` ne modifie jamais le Soul Snapshot. Toute évolution de personnalité passe par la création explicite d'un autre snapshot lié au précédent.

# Kristal et Âme Artificielle

## Statut
**Architecture d’intégration proposée**

---

## Principe

Kristal sert de **couche de représentation, provenance, identité et distribution** du Soul Graph.

L’Âme Artificielle Engine reste le moteur qui interprète ce graphe.

```text
Kristal
  -> Soul Snapshot structuré
  -> Runtime representation
  -> Soul Causal Engine
  -> Activation Graph
  -> Reaction
```

Kristal ne devient pas le moteur psychologique.

---

## Structured Epistemic State

Un Soul Snapshot peut être représenté comme un **Structured Epistemic State** contenant des assertions sur :

- les croyances du sujet ;
- ses associations ;
- ses valeurs ;
- ses souvenirs structurants ;
- ses dispositions ;
- les relations psycho-causales proposées ;
- leur provenance ;
- leur période de validité ;
- leur niveau de certitude.

---

## Profil de projet

L’intégration peut définir un profil spécifique, par exemple :

```text
kristal.v5:soul-graph
```

Ce nom désigne une **extension du projet Âme Artificielle**, pas un profil déjà standardisé par Kristal.

Le profil définirait :

- les types de nœuds ;
- les prédicats psycho-causaux ;
- les qualificateurs de force et d’activation ;
- les règles de snapshot ;
- les projections de traits ;
- les contraintes de déterminisme du moteur.

---

## Certitude vs force psychologique

Cette séparation est obligatoire.

```text
belief_strength = 0.9
```

signifie : John adhère fortement à cette croyance.

```text
certainty_level = high
```

signifie : les sources du modèle donnent une forte confiance au fait que John possède cette croyance.

Les deux ne doivent jamais être confondus.

---

## Assertions symboliques

Les propositions issues de la numérologie, des cartes natales ou des branes peuvent être conservées avec un statut explicite : hypothèse, modèle symbolique, matériau de recherche, etc.

Elles peuvent donc coexister avec des observations biographiques sans être silencieusement fusionnées.

---

## Snapshot et identité

Chaque snapshot possède une identité stable et reproductible.

Une modification explicite du graphe produit un **nouvel état**, plutôt qu’une mutation silencieuse du précédent.

Cela correspond naturellement au modèle d’artefacts adressés par contenu de Kristal.

---

## Limite des requêtes

Le moteur causal ne doit pas dépendre du fait que Kristal offre ou non un raisonnement de graphe complet.

Kristal fournit les données structurées. Le Soul Causal Engine construit les index et mécanismes nécessaires à la propagation d’activation.

---

## Formulation canonique

> Kristal conserve le Soul Graph comme état épistémique structuré, traçable et versionné. Le Soul Causal Engine utilise cet état pour effectuer la propagation psycho-causale. La persistance de la connaissance et le calcul de la réaction restent deux responsabilités distinctes.

# Mécanisme de Réaction

## Statut
**Page canonique**

---

## Définition

Une réaction n’est pas calculée à partir d’un seul trait ni d’une chaîne fixe. Elle résulte de l’**activation temporaire d’un sous-graphe psycho-causal** appartenant au Soul Snapshot du sujet.

Forme minimale :

```text
Soul Snapshot + stimulus + contexte
        -> Activation Graph
        -> interprétation
        -> état affectif / intention
        -> réaction
```

Le Soul Snapshot reste inchangé.

---

## 1. Réception sémantique

Le stimulus est transformé en concepts exploitables : personnes, objets, actions, thèmes, relations et contexte.

Exemple :

```text
« Ton collègue a obtenu la promotion que tu voulais. »
```

peut activer :

- collègue ;
- compétition ;
- reconnaissance ;
- perte ;
- comparaison sociale ;
- autorité ;
- souvenirs associés.

---

## 2. Sélection des nœuds pertinents

Le moteur recherche dans le Soul Snapshot les nœuds reliés sémantiquement aux concepts du stimulus.

La sélection peut utiliser :

- identifiants et relations explicites ;
- labels et alias ;
- catégories ;
- similarité sémantique locale ;
- règles contextuelles.

Une similarité sémantique ne constitue pas encore une relation causale. Elle sert seulement à trouver les points d’entrée possibles.

---

## 3. Propagation psycho-causale

L’activation se propage ensuite uniquement sur les relations autorisées par le moteur, par exemple :

- `activates` ;
- `inhibits` ;
- `reinforces` ;
- `predisposes_to` ;
- `contributes_to`.

Le moteur doit pouvoir représenter :

- plusieurs causes pour un même effet ;
- plusieurs effets pour une même activation ;
- des boucles ;
- des conflits ;
- des inhibitions ;
- des seuils ;
- de la décroissance d’activation.

Pour éviter une propagation infinie, l’exécution peut imposer un nombre maximal d’étapes, une décroissance et un seuil minimal.

---

## 4. Intervention de l’intellect

L’intellect peut modifier l’interprétation produite par une activation initiale.

Exemple :

```text
réaction automatique
    -> comparaison à une croyance explicite
    -> détection d’une contradiction
    -> réévaluation
    -> inhibition d’un chemin initial
```

Ainsi, deux personnes ayant une sensibilité affective semblable peuvent produire des réactions différentes parce que leurs modèles intellectuels et leurs croyances explicites diffèrent.

---

## 5. État affectif transitoire

L’émotion n’est pas nécessairement stockée comme une valeur fixe de personnalité.

Elle peut être dérivée de la configuration d’activation :

```text
menace perçue + attachement + possibilité de perte
-> peur / jalousie / vigilance
```

Les noms d’émotions sont des **interprétations du résultat**, non l’unique unité de calcul.

---

## 6. Intention et réaction

Le moteur produit d’abord une représentation structurée de la réaction :

- interprétation dominante ;
- tensions actives ;
- état affectif ;
- intention ;
- tendances de réponse ;
- chemins explicatifs principaux.

Une couche de rendu peut ensuite transformer cette structure en texte, geste simulé ou autre sortie.

---

## Rôle de la charte 1→9

La charte 1→9 n’est plus le chemin unique que tout stimulus doit suivre.

Elle devient une **topologie de lecture** permettant de classer certains nœuds ou certaines étapes : cognition, expression, relation, affect, instinct, etc.

Un même mécanisme peut concerner plusieurs niveaux.

Voir : [Charte 1→9 et Chakras](./CHARTE_1_9_ET_CHAKRAS).

---

## Rôle de la numérologie et de la carte natale

Elles ne déterminent pas directement la réaction.

Elles peuvent proposer des **dispositions initiales hypothétiques** qui deviennent des nœuds ou des poids dans le Soul Snapshot. Leur valeur prédictive doit être évaluée expérimentalement.

---

## Sécurité

La sécurité logicielle intervient **après ou autour du moteur**, comme contrainte d’exécution.

Elle ne doit pas être confondue avec :

- la compassion du personnage ;
- sa morale ;
- sa personnalité ;
- son émotion ;
- son mécanisme causal.

Une personnalité simulée peut avoir une intention que l’application refuse d’exécuter. Cette limitation appartient au logiciel, pas à la définition de l’âme.

---

## Formulation canonique

> Une réaction est le résultat d’une activation transitoire et bornée du graphe psycho-causal d’un sujet. Le stimulus sélectionne des points d’entrée, les relations pertinentes propagent ou inhibent l’activation, l’intellect peut réévaluer l’interprétation, puis le moteur produit un état affectif, une intention et une réaction sans modifier automatiquement la personnalité persistante.

# Numérologie Pythagoricienne Inversée

## Statut
**Couche hypothétique et archétypale**

---

## Définition

La **numérologie pythagoricienne inversée** est une grammaire symbolique utilisée par le projet pour proposer des correspondances entre des signatures numériques et des **dispositions possibles**.

Elle ne constitue pas, à elle seule, une personnalité et ne détermine pas directement les réactions.

---

## Réduction et inversion

Après une réduction à 1–9, le projet peut appliquer :

```text
inv(d) = 10 - d, pour d dans 1..9
```

ce qui donne :

```text
1 <-> 9
2 <-> 8
3 <-> 7
4 <-> 6
5 <-> 5
```

Le 5 reste le pivot.

---

## Nouveau rôle dans l’architecture

Ancien modèle simplifié :

```text
digit -> traits -> personnalité
```

Nouveau modèle :

```text
signature numérique
  -> interprétation archétypale
  -> hypothèses de dispositions
  -> nœuds / poids proposés dans le Soul Graph
  -> confrontation à la biographie et aux observations
```

Une correspondance numérologique est donc une **source de propositions**, non une preuve de personnalité.

---

## Dualités

Les paires historiques sont conservées :

- 9 ↔ 1
- 8 ↔ 2
- 7 ↔ 3
- 6 ↔ 4
- 5 comme pivot

Elles peuvent servir à proposer :

- des polarités ;
- des tensions ;
- des complémentarités ;
- des axes de comparaison.

Elles ne sont pas automatiquement des relations causales. Une relation causale doit être représentée séparément dans le graphe.

---

## Numérologie, inné et acquis

Le projet peut tester l’hypothèse que certaines signatures correspondent à des dispositions relativement initiales.

Dans ce cas, une disposition proposée peut être annotée :

```text
origin = hypothesized_innate
source_model = inverted_pythagorean_numerology
```

La biographie peut ensuite confirmer, nuancer ou contredire cette proposition.

---

## Distinction avec la charte 1→9

Même si les deux utilisent 1–9 :

- la numérologie décrit une **lecture archétypale** ;
- la charte décrit une **topologie fonctionnelle** ;
- le graphe psycho-causal décrit les **mécanismes et relations effectifs du modèle**.

---

## Formulation canonique

> La numérologie pythagoricienne inversée est une couche symbolique permettant de générer des hypothèses de dispositions et de polarités. Ces hypothèses peuvent alimenter un Soul Snapshot, mais elles doivent rester identifiables, documentées et séparées des observations biographiques et des résultats expérimentaux.

# Snapshots et Évolution

## Statut
**Page canonique**

---

## Principe

Une personne change dans le temps, mais l’Âme Artificielle ne s’auto-met pas à jour pendant une conversation.

Le projet représente l’évolution par une suite de **Soul Snapshots immuables**.

```text
John @ 18 ans -> John @ 30 ans -> John @ 45 ans
```

La flèche ne représente pas un apprentissage automatique du moteur. Elle représente une transformation **décrite explicitement** lors de la construction du nouveau snapshot.

---

## Pourquoi des snapshots

Cette approche permet :

- de reproduire un âge précis ;
- de comparer deux périodes de vie ;
- de retracer les causes proposées d’un changement ;
- de conserver la provenance ;
- de tester la cohérence historique ;
- d’éviter qu’une conversation fictive modifie silencieusement le modèle d’une personne réelle.

---

## Transformation biographique

Une transformation biographique décrit ce qui a changé et pourquoi.

Exemples :

- croyance abandonnée ;
- croyance reformulée ;
- association affaiblie ;
- valeur renforcée ;
- nouvel attachement ;
- stratégie intellectuelle acquise ;
- événement traumatique ;
- expérience corrective ;
- maturation ou changement de contexte.

---

## Exemple : révision d’un préjugé

Snapshot initial :

```text
Groupe X -> association négative -> méfiance
```

Événement biographique :

```text
Bob appartient à X
John et Bob ont une forte compatibilité
expériences positives répétées
```

Révision :

```text
expérience avec Bob
  contradicts -> généralisation négative

réévaluation intellectuelle
  weakens -> association X -> menace
```

Snapshot ultérieur :

```text
appartenance à X
  n’active plus automatiquement -> méfiance
```

Le modèle ne suppose pas qu’une seule amitié produit nécessairement ce résultat chez tout humain. Il encode explicitement que, **dans la biographie modélisée de ce sujet**, cette série d’expériences a été considérée comme causalement importante.

---

## Identité et continuité

Deux snapshots différents représentent la même personne historique si leur identité de sujet est commune, même si leur contenu psycho-causal diffère.

Il faut donc distinguer :

- `person_id` — identité de la personne modélisée ;
- `snapshot_id` — identité du modèle à une période ;
- `valid_during` — période représentée ;
- `derived_from_snapshot` — relation de filiation technique ;
- les assertions biographiques — explication psycho-causale du changement.

---

## Formulation canonique

> L’évolution d’une personnalité est représentée par plusieurs snapshots immuables d’une même personne. Les différences entre snapshots sont expliquées par des transformations biographiques explicites ; elles ne sont pas apprises automatiquement pendant l’interaction.
