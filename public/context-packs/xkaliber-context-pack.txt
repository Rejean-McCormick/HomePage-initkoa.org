# Branding — XKaliber

## Nom

**XKaliber**

## Signature

**L’épreuve qui révèle le vrai calibre.**

## Promesse

XKaliber mesure une compétence contextualisée afin de rendre visible ce qui est confirmé, ce qui est seulement exploré et dans quelles limites le résultat peut être utilisé.

## Phrase maîtresse

**XKaliber révèle le calibre d’une compétence, pas la valeur d’une personne.**

## Métaphore

| Mythe arthurien | XKaliber dans Konnaxion |
|---|---|
| L’épée dans la pierre | La compétence encore non révélée |
| L’épreuve d’extraction | L’évaluation adaptative XKaliber |
| Celui qui peut porter la fonction | Une capacité confirmée dans un scope explicite |
| La Table ronde | La gouvernance collective opérante dans Konnaxion |
| La quête | Le passage de l’apprentissage à une preuve contextualisée |

## Ton de marque

XKaliber doit être :

- précis ;
- sobre ;
- exigeant ;
- humain ;
- non humiliant ;
- non technocratique ;
- orienté vers la capacité et les limites plutôt que le classement.

## Ce que la marque ne doit pas suggérer

- une élite permanente ;
- un score global de personne ;
- une autorité universelle ;
- une compétence valable hors domaine ;
- l’absence de recours ;
- une fusion entre compétence, réputation et pouvoir de décision.

## Vocabulaire produit

| Concept | Terme XKaliber |
|---|---|
| Test adaptatif | Épreuve XKaliber |
| Rapport final | Profil de Calibre |
| Niveau confirmé | Calibre validé |
| Niveau maximal exploré | Portée maximale explorée |
| Compétence fiable | Maîtrise confirmée |
| Preuve exportable XKaliber | Assessment Evidence Package / preuve d’évaluation |
| Réévaluation périodique | Recalibrage |
| Groupe de validation | Table de validation |

Le **Sceau CertifiKation** est un artifact downstream de CertifiKation, pas un artifact que XKaliber s’auto-attribue.

## Formule d’architecture

**KonnectED développe.**  
**XKaliber éprouve et mesure.**  
**CertifiKation atteste.**  
**K-Port qualifie l’évidence.**  
**EkoH situe la réputation par domaine.**  
**Smart Vote produit des readings contextuelles lorsque ses règles l’autorisent.**

# XKaliber — Conceptual contracts

These technology-neutral contracts define **XKaliber-owned** domain objects and events.

They intentionally stop at XKaliber’s authority boundary.

## XKaliber-owned

- candidate assessment reference;
- competency domain/competency definitions used by the assessment;
- assessment items;
- assessment sessions;
- Caliber Profile;
- Assessment Evidence Package;
- assessment lifecycle/events.

## Not XKaliber-owned

- CertifiKation attestation/seal;
- K-Port claim/admissibility state;
- EkoH reputation signal/score;
- Smart Vote reading.

External adapters may map XKaliber evidence into those systems’ contracts, but their objects do not belong in the XKaliber core domain model.

# Décision 0001 — Nom et positionnement

## Statut

Acceptée comme base de départ.

## Décision

Nommer l’application **XKaliber**.

Positionnement :

**XKaliber est le moteur de mesure adaptative des compétences de CertifiKation, dans KonnectED.**

## Raison

Le nom fait le pont entre :

- Excalibur comme épreuve de légitimité ;
- calibre comme mesure réelle ;
- X comme inconnue à révéler ;
- K comme cohérence avec Konnaxion, KonnectED et CertifiKation.

## Conséquence

La marque peut utiliser l’imaginaire de l’épée et de la Table ronde, mais doit éviter une logique monarchique ou élitiste.

La métaphore doit rester fonctionnelle : XKaliber ne couronne pas, il situe la capacité à porter une responsabilité.

# XKaliber — Data boundaries

## Layers

XKaliber distinguishes:

1. **Session evidence** — responses, tasks, timing/context, progression.
2. **Scoring interpretation** — level estimate, confidence, observed limitations.
3. **Caliber Profile** — readable assessment result.
4. **Assessment Evidence Package** — minimal exportable XKaliber evidence.
5. **CertifiKation attestation** — downstream artifact owned by CertifiKation.
6. **K-Port admissibility state** — downstream evidence-gateway decision.
7. **EkoH reputation state** — downstream reputation calculation.
8. **Smart Vote reading** — downstream declared reading.
9. **External decision** — hiring/access/governance decision outside XKaliber.

```text
session evidence
≠ profile
≠ evidence export
≠ attestation
≠ admissibility
≠ reputation
≠ reading
≠ external decision
```

## Disclosure gradient

The farther the use is from the assessment, the smaller and more scoped the data projection should be.

Examples:

- the assessed person/evaluator may need detailed session evidence;
- CertifiKation needs evidence sufficient to attest the confirmed competency;
- K-Port needs a minimal verifiable evidence package plus consent/use limits;
- EkoH receives a governed handoff from K-Port, not raw responses;
- Smart Vote receives governed EkoH context, not XKaliber session data.

# XKaliber — Internal responsibility map

The following are **internal responsibilities**, not peer ecosystem systems.

## Assessment Designer

Defines domains, competencies, levels, item types, evaluation criteria and validity conditions.

## Item Bank

Owns assessment items/tasks with competency, difficulty, scoring criteria, bias notes, validation status and version.

## Adaptive Engine

Selects next work based on observed performance, uncertainty, target competency, fatigue/time constraints and declared rules.

## Assessment Session

Owns the running assessment lifecycle: consent reference, start, items, responses, pauses/incidents and completion.

## Scoring and Interpretation

Transforms observed evidence into confirmed level, explored level, confidence, limitations and recommendations under a versioned rule set.

## Caliber Profile

Produces the human-readable assessment result.

## Evidence Export

Produces an `AssessmentEvidencePackage` for an authorized external consumer.

It does not issue CertifiKation artifacts and does not produce EkoH reputation state.

## Governance/Audit

Preserves rule versions, interventions, contestations and corrections.

## Integration adapters

Map XKaliber outputs to explicit external boundaries such as KonnectED, CertifiKation and K-Port without importing their internal authority into the assessment core.

# XKaliber — Architecture conceptuelle

## Définition

XKaliber est une **application / assessment engine technology-agnostic** qui transforme des performances observées en profils de compétence contextualisés.

Il appartient à la frontière CertifiKation / KonnectED de Konnaxion. Il n’est pas un ecosystem system peer de Konnaxion.

## Pipeline

```text
Assessment request + consent
        ↓
initial estimate
        ↓
adaptive assessment session
        ↓
observed evidence
        ↓
scoring / interpretation
        ↓
Caliber Profile
        ↓
Assessment Evidence Package
        ├──→ CertifiKation (attestation when applicable)
        └──→ K-Port (evidence admissibility when EkoH use is requested)
```

## Internal responsibilities

- competency/domain definitions used by assessment;
- item bank semantics;
- adaptive engine;
- assessment session;
- scoring/interpretation;
- Caliber Profile;
- assessment evidence export;
- audit, correction and contestation of the assessment result.

## External responsibilities

- **KonnectED** — learning/path/portfolio context;
- **CertifiKation** — attestation/seal authority;
- **K-Port** — canonical evidence gateway toward EkoH;
- **EkoH** — domain-bounded reputation impact;
- **Smart Vote** — declared readings using governed context when allowed.

## Non-transfer rule

```text
XKaliber measurement
≠ CertifiKation attestation
≠ K-Port admissibility
≠ EkoH reputation
≠ Smart Vote reading
```

# XKaliber — Ownership and boundaries

## 1. Category

XKaliber is an **application + adaptive competency assessment engine** inside Konnaxion’s KonnectED/CertifiKation capability boundary.

`module` may be used informally in Konnaxion product language, but it is not the architecture category used here.

## 2. XKaliber owns

- assessment semantics;
- observed performance evidence;
- adaptive rule/version used;
- assessment session state;
- scoring interpretation;
- confidence/uncertainty semantics;
- Caliber Profile;
- assessment result status: active/corrected/contested/expired as defined by the profile contract;
- Assessment Evidence Package;
- assessment audit and review state.

## 3. CertifiKation owns

When CertifiKation is used, it owns the **attestation decision and attestation artifact/lifecycle**.

XKaliber supplies evidence. It does not self-issue a CertifiKation seal.

## 4. K-Port owns

For EkoH-bound evidence, K-Port owns:

- provenance/integrity/admissibility checks;
- identity binding for the handoff;
- deduplication/supersession rules in its evidence scope;
- consent/use-limit checks;
- mapping into canonical EkoH domains;
- decision whether evidence is eligible for EkoH handoff.

K-Port does not re-score XKaliber performance.

## 5. EkoH owns

- domain reputation score state;
- reputation-impact policy;
- combination with other admissible evidence;
- reputation history/audit in its domain.

XKaliber does not construct an EkoH score or EkoH-owned signal object.

## 6. Smart Vote owns

Smart Vote owns declared reading/lens semantics. It may consume governed EkoH context according to Konnaxion policy.

XKaliber does not write Smart Vote ballots/readings and Smart Vote does not receive raw XKaliber responses by default.

## 7. KonnectED

KonnectED can provide learning/context inputs and can display/store authorized profile/attestation references. It does not rewrite the XKaliber measurement result.

## 8. Contestation routing

```text
assessment result          → XKaliber
attestation/seal           → CertifiKation
K-Port admissibility       → K-Port
EkoH reputation impact     → EkoH
Smart Vote reading/policy  → Smart Vote / relevant Konnaxion governance
```

# Modèle d’évaluation adaptative

## But

Trouver le niveau où une compétence demeure fiable.

## Étapes

### 1. Scan initial

Le système estime un niveau de départ à partir de :

- autoévaluation ;
- parcours KonnectED ;
- antécédents CertifiKation ;
- mini-épreuve ;
- expérience déclarée ;
- recommandation d’un évaluateur.

Le scan initial ne certifie rien. Il sert à choisir un point de départ raisonnable.

### 2. Zone de maîtrise

Le système propose des tâches qu’une personne de ce niveau devrait réussir avec un haut taux de réussite.

Objectif : confirmer sans déstabiliser.

### 3. Zone de précision

Si la personne réussit trop facilement, le système augmente la difficulté.

Objectif : éviter l’effet plafond.

### 4. Épreuve du Tranchant

Le système explore un niveau supérieur pour vérifier jusqu’où la personne peut aller.

Objectif : mesurer la portée maximale, pas seulement la compétence de base.

### 5. Stabilisation

Le système s’arrête quand :

- le niveau confirmé est assez clair ;
- le niveau supérieur est suffisamment exploré ;
- la fatigue ou le temps devient une contrainte ;
- l’incertitude ne peut plus être réduite utilement ;
- un seuil de certification est atteint ou refusé.

## Règle intuitive

- Trop facile : on ne mesure pas le plafond.
- Trop difficile : on mesure surtout l’échec.
- Bon niveau : la personne reste engagée, mais le système apprend quelque chose.

## Sortie

La sortie n’est pas seulement une note. Elle indique :

- ce qui est confirmé ;
- ce qui est partiel ;
- ce qui est non mesuré ;
- ce qui devrait être réévalué ;
- ce qui peut être attesté.

# XKaliber — Caliber Profile

## Definition

The **Caliber Profile** is XKaliber's primary human-readable assessment result.

It is distinct from:

- raw session evidence;
- Assessment Evidence Package;
- CertifiKation attestation;
- K-Port admissibility state;
- EkoH reputation state.

## Intended readers

Depending on consent and policy, the profile can be read by:

- the assessed person;
- an evaluator/former;
- an organization;
- KonnectED;
- CertifiKation as an assessment consumer.

K-Port should normally receive a scoped `AssessmentEvidencePackage` rather than the complete human-facing profile unless its contract explicitly requires more.

## Recommended structure

```text
Profile ID: [...]
Person/subject reference: [...]
Domain: [...]
Competency: [...]
Assessment context: [...]
Assessment date: [...]
Rule version: [...]

Result:
- Confirmed level: [...]
- Highest explored level: [...]
- Confidence/uncertainty: [...]
- Status: [...]

Interpretation:
- Observed strengths
- Observed limitations
- Important errors/uncertainties
- Validity conditions
- Recommendations

Traceability:
- assessment/session reference
- item/rule versions as permitted
- human interventions
- interpretation limits
- review/contestation reference when applicable
```

## Certification recommendation

XKaliber may state that the evidence appears suitable for CertifiKation review. It does **not** itself turn that recommendation into a CertifiKation attestation.

Example:

```text
Confirmed level: 3
Explored level: 4
Confidence: medium-high
Recommendation: submit Assessment Evidence Package to CertifiKation for level-3 attestation review; recalibrate level 4 after targeted practice.
```

# Liste de vérification — équité

## Avant publication d’une épreuve

- [ ] La compétence évaluée est clairement définie.
- [ ] Le niveau de difficulté est justifié.
- [ ] Les consignes sont compréhensibles.
- [ ] Les critères de correction sont explicites.
- [ ] Les biais linguistiques ont été examinés.
- [ ] Les biais culturels ont été examinés.
- [ ] La tâche mesure bien la compétence visée.
- [ ] Des accommodations sont prévues si nécessaire.
- [ ] Un recours humain est possible.
- [ ] Les limites d’interprétation sont affichées.

## Après usage

- [ ] Les anomalies de résultat sont examinées.
- [ ] Les différences entre groupes sont surveillées.
- [ ] Les plaintes sont analysées.
- [ ] Les items problématiques sont retirés ou corrigés.
- [ ] Les seuils sont révisés périodiquement.
- [ ] Les profils peuvent être recalibrés.

## Question clé

**Est-ce que cette épreuve mesure la compétence, ou mesure-t-elle autre chose par accident ?**

# Guide de conception des items et tâches

## Chaque item doit préciser

- domaine ;
- compétence ;
- niveau ;
- type de tâche ;
- consigne ;
- durée ;
- critères de correction ;
- erreurs observables ;
- prérequis ;
- risques de biais ;
- version ;
- statut de validation.

## Types d’épreuves

### Question fermée

Utile pour vérifier des connaissances précises.

### Question ouverte

Utile pour analyser le raisonnement.

### Étude de cas

Utile pour juger l’application en contexte.

### Simulation

Utile pour observer une décision dynamique.

### Production

Utile pour évaluer la capacité à créer un résultat.

### Revue par pairs

Utile lorsque la qualité exige un jugement humain.

### Entrevue structurée

Utile pour compléter une mesure automatisée.

## Qualité d’un item

Un bon item :

- cible une compétence claire ;
- évite les pièges inutiles ;
- distingue les niveaux ;
- permet une correction stable ;
- réduit les biais culturels inutiles ;
- explique ce qui est attendu ;
- peut être révisé.

## Items à éviter

- questions ambiguës ;
- devinettes ;
- références culturelles non pertinentes ;
- vitesse excessive sans raison ;
- pièges linguistiques ;
- tâches qui mesurent surtout la familiarité avec le format du test ;
- tâches qui confondent conformité et compétence.

# Principes de score et d’interprétation

## Ne pas réduire à une note

Une note brute peut être conservée pour audit, mais elle ne doit pas être la sortie principale.

La sortie principale est le **Profil de Calibre**.

## Dimensions du profil

### Calibre validé

Niveau confirmé avec confiance suffisante.

### Portée maximale

Niveau le plus élevé exploré où la personne montre encore une capacité réelle.

### Marge de confiance

Niveau d’incertitude du résultat.

### Type de maîtrise

- procédurale ;
- conceptuelle ;
- créative ;
- stratégique ;
- relationnelle ;
- éthique ;
- contextuelle.

### Conditions de validité

Contexte où le résultat est valable.

### Conditions de non-validité

Ce que le résultat ne permet pas de conclure.

## Interprétation recommandée

| Résultat observé | Interprétation prudente |
|---|---|
| Réussite élevée sur tâches faciles | Maîtrise confirmée, plafond non mesuré |
| Réussite élevée sur tâches difficiles | Niveau supérieur probable |
| Réussite moyenne sur tâches difficiles | Zone de précision utile |
| Échec sur tâches trop difficiles | Ne prouve pas absence de compétence au niveau inférieur |
| Forte variabilité | Recalibrage ou évaluation humaine recommandé |

## Seuils à éviter

Ne jamais dire :

- “Cette personne est compétente en général.”
- “Cette personne vaut X.”
- “Cette personne ne peut pas apprendre.”
- “Cette personne est inférieure.”
- “Cette personne peut décider sur tous les sujets.”

Dire plutôt :

- “Cette compétence est confirmée jusqu’au niveau X dans le contexte Y.”
- “Le niveau supérieur est partiellement démontré.”
- “Une évaluation complémentaire est recommandée.”

# XKaliber — Audit requirements

## Traceable assessment facts

- assessment request and purpose;
- consent scope/status;
- domain/competency versions;
- item versions presented;
- adaptive-rule version;
- difficulty transitions and declared reasons;
- responses/productions according to retention policy;
- human interventions;
- anomalies;
- scoring/interpretation rule version;
- Caliber Profile creation/correction/contestation;
- Assessment Evidence Package exports and consumer identity;
- relevant consent/use limits at export time.

## Explainable result

The system must be able to explain:

- why a level was confirmed;
- why a higher level was not confirmed;
- why difficulty changed;
- what uncertainty remains;
- what validity/use limits apply;
- how to contest the result.

## Downstream boundaries

XKaliber may record that evidence was exported to CertifiKation or K-Port. It does not duplicate the downstream authoritative audit for CertifiKation issuance, K-Port admissibility, EkoH scoring or Smart Vote readings.

# XKaliber — Decision-use policy

## Principle

XKaliber informs a decision with domain-bounded competency evidence. It does not, by itself, decide high-impact outcomes.

## Acceptable uses

- guide learning;
- recommend training;
- support competency attestation;
- inform a structured hiring/review process;
- prepare an interview;
- provide evidence to K-Port/EkoH under consent and scope rules;
- support transparent collective governance through governed downstream interfaces.

## High-impact uses require stronger controls

Examples:

- refusal of employment/access;
- exclusion from a program;
- loss of status;
- public profile publication;
- use of EkoH context in a Smart Vote reading.

Controls should include explanation, scope validation, human review where appropriate, contestability and explicit downstream policy.

## Forbidden by default

- automatic high-impact decision without recourse;
- global human score;
- out-of-domain use;
- forced public ranking;
- continuous surveillance unrelated to assessment;
- direct XKaliber → EkoH reputation write;
- direct XKaliber → Smart Vote weighting/readings.

# XKaliber → CertifiKation evidence

## Principle

XKaliber **measures**. CertifiKation **attests**.

XKaliber therefore exports evidence sufficient for CertifiKation to make its own attestation decision. XKaliber does not self-issue a `CertifiKationSeal` as an XKaliber-owned domain object.

## Assessment Evidence Package

Recommended fields:

- evidence/package ID;
- source system/application = XKaliber;
- candidate/subject reference under the permitted identity model;
- source Caliber Profile ID;
- assessment/session reference;
- domain ID;
- competency ID;
- confirmed level;
- explored level when needed;
- confidence/uncertainty;
- assessment date;
- rule version;
- validity conditions;
- status of the source result;
- usage limits;
- consent reference;
- audit/verification reference;
- integrity/provenance metadata as required by the implementation.

## CertifiKation boundary

CertifiKation may:

- verify the XKaliber evidence;
- decide whether it is sufficient for attestation;
- issue, expire, correct, contest or revoke its own attestation artifact under its contract.

CertifiKation does not alter XKaliber’s source measurement. If the underlying assessment is wrong, correction returns to XKaliber.

## Downstream K-Port

K-Port may receive either a valid XKaliber evidence package or a CertifiKation attestation if its evidence policy permits it. K-Port determines admissibility for EkoH; it does not recalculate the XKaliber result.

# Handoff vers K-Port, EkoH et SmartVote

## Principe

XKaliber peut contribuer à la crédibilité par domaine, mais il ne doit ni créer une autorité globale ni écrire directement dans la réputation EkoH.

La chaîne canonique est :

```text
XKaliber
→ Profil de Calibre / résultat confirmé
→ Sceau CertifiKation, lorsque applicable
→ K-Port
→ signal de scoring admissible
→ EkoH
→ usages gouvernés, dont SmartVote lorsque permis
```

**K-Port est la passerelle canonique d’évidence vers EkoH.**

## Paquet d’évidence minimal vers K-Port

Une preuve XKaliber ou CertifiKation transmise à K-Port devrait contenir au minimum :

- identifiant de la personne ou référence d’identité autorisée ;
- `source_module` : `xkaliber` ou `certifikation` ;
- identifiant stable du Profil de Calibre ou du Sceau ;
- domaine ;
- compétence ;
- niveau confirmé ;
- date de l’évaluation ;
- date d’émission de la preuve, si différente ;
- confiance ou marge de confiance ;
- durée de validité ou date d’expiration ;
- version des règles / de l’épreuve ;
- statut : actif, expiré, contesté, corrigé ou révoqué ;
- limites d’usage ;
- consentement et visibilité ;
- référence d’audit ou mécanisme de vérification de provenance.

## Autorité source et contrôle K-Port

Pour une preuve XKaliber valide, K-Port doit distinguer deux responsabilités :

**XKaliber / CertifiKation sont autoritatifs pour :**

- la performance observée ;
- le niveau confirmé ;
- la confiance issue de l’évaluation ;
- les règles et versions ayant produit le résultat ;
- les corrections ou révocations de cette preuve.

**K-Port est autoritatif pour :**

- vérifier que la preuve provient bien de XKaliber / CertifiKation ;
- lier la preuve à la bonne personne ;
- vérifier le statut, l’expiration et les révocations ;
- vérifier les limites et le consentement ;
- prévenir les doublons ;
- mapper ou confirmer la correspondance avec les domaines EkoH ;
- déterminer si l’évidence est admissible au handoff EkoH.

K-Port **ne doit pas refaire l’épreuve, modifier le niveau confirmé ou recalculer la confiance XKaliber**. Toute contestation de la mesure retourne au processus de révision XKaliber / CertifiKation.

## Signal EkoH

XKaliber ne construit pas le score de réputation. K-Port prépare le handoff à partir de l’évidence admissible, puis EkoH décide :

- si la preuve doit avoir un impact ;
- sur quel domaine EkoH ;
- avec quel poids selon ses paramètres ;
- comment la fraîcheur, les autres preuves et les règles de réputation interagissent ;
- comment le changement est consigné dans l’historique de score.

La confiance XKaliber est un **attribut de la preuve**, pas un score EkoH.

## Ce qu’il ne faut pas envoyer par défaut

Ni K-Port, ni EkoH, ni SmartVote ne devraient recevoir par défaut :

- réponses brutes ;
- temps détaillés ;
- erreurs personnelles sensibles ;
- commentaires privés ;
- données non nécessaires ;
- interprétations hors domaine.

## Usage SmartVote

SmartVote peut utiliser des signaux de compétence ou de réputation seulement si :

- le signal provient d’une interface gouvernée d’EkoH plutôt que directement de XKaliber ;
- le domaine du vote correspond au domaine validé ;
- les règles de pondération sont publiques ;
- les lectures non pondérées restent visibles ;
- la personne sait que le signal est utilisé ;
- la communauté peut contester la règle ;
- le signal est limité dans le temps.

## Propagation des changements

Une correction, expiration ou révocation XKaliber / CertifiKation doit pouvoir se propager vers K-Port. K-Port met alors à jour l’état de l’évidence et déclenche, si nécessaire, une réévaluation de l’impact par EkoH. XKaliber ne corrige pas directement un score EkoH.

## Phrase clé

**XKaliber mesure ; K-Port qualifie l’évidence ; EkoH attribue la réputation ; SmartVote n’utilise que des signaux gouvernés.**

**Domaine :** Analyse de données

- Lit correctement les tableaux simples et intermédiaires.

- l’analyse statistique avancée ;
- la modélisation prédictive ;
- la conception de bases de données ;
- la décision stratégique autonome.

## Recommandation

Soumettre le résultat à CertifiKation pour une attestation de niveau 3. Prévoir un parcours KonnectED ciblé pour consolider le niveau 4, suivi d’un recalibrage.

# XKaliber — Gouvernance de l’évaluation

## Principe directeur

XKaliber ne devient jamais un outil de classement total des personnes. Il mesure des compétences contextualisées, dans des domaines précis, sous des règles explicites, versionnées et contestables.

## Invariants

1. **Domaine avant score** — toute mesure appartient à un domaine et une compétence précis.
2. **Observation avant interprétation** — performance observée, interprétation et décision d’usage restent distinguées.
3. **Preuve avant usage downstream** — un signal ne quitte pas XKaliber sans evidence/provenance suffisante.
4. **Explication avant usage** — le résultat et ses limites sont compréhensibles.
5. **Recours avant sanction** — une décision importante fondée sur le résultat permet une revue humaine appropriée.
6. **Temporalité avant permanence** — profils et evidence peuvent expirer, être corrigés ou recalibrés.
7. **Contexte avant généralisation** — une compétence n’accorde aucune autorité hors scope.
8. **Séparation des autorités** — XKaliber mesure, CertifiKation atteste, K-Port qualifie l’evidence, EkoH calcule la réputation.

## Autorité des règles d’évaluation

Les éléments suivants sont versionnés et audités :

- competency domains ;
- competency levels ;
- item versions ;
- scoring criteria ;
- adaptive rules ;
- stopping rules ;
- confidence rules ;
- validity conditions ;
- correction/review rules.

## Rôles

### Mainteneur produit

Responsable de la cohérence fonctionnelle de XKaliber.

### Gardien de l’évaluation

Responsable des principes de mesure, seuils, effets plafond/plancher et qualité des épreuves.

### Gardien de l’équité

Responsable des biais, impacts sociaux, accessibilité et limites d’usage.

### Table de validation

Groupe compétent dans un domaine qui valide niveaux, critères et types d’épreuves.

### Auditeur

Peut vérifier les traces, règles et sorties sous les permissions applicables.

## Usages interdits

XKaliber ne doit pas être utilisé pour :

- produire un score global de valeur humaine ;
- exclure automatiquement sans recours ;
- classer publiquement sans consentement ;
- utiliser une compétence hors domaine ;
- confondre performance ponctuelle et identité permanente ;
- écrire directement une réputation EkoH ;
- calculer une reading Smart Vote en contournant EkoH/Smart Vote.

# Product brief — XKaliber

## Définition

XKaliber est une **application / moteur d’évaluation adaptative des compétences** dans la frontière CertifiKation / KonnectED de Konnaxion.

Il transforme des performances observées sous des règles versionnées en un **Profil de Calibre** et en une **preuve d’évaluation structurée**.

## Problème

Les tests classiques posent plusieurs problèmes :

- même niveau de difficulté pour tous ;
- effet plafond pour les personnes très compétentes ;
- effet plancher pour les personnes moins avancées ;
- stress inutile quand le test est trop difficile ;
- surconfiance quand le test est trop facile ;
- notes difficiles à interpréter dans un contexte réel ;
- faible capacité à indiquer ce qui est réellement confirmé, seulement exploré ou encore incertain.

## Proposition

XKaliber ajuste la difficulté selon la performance observée afin de situer la personne dans une zone de mesure utile.

Deux moments structurent l’évaluation :

1. **Validation confortable** — confirmer le niveau qui devrait être maîtrisé avec fiabilité.
2. **Exploration du plafond** — augmenter la difficulté lorsque la performance est trop élevée afin d’identifier jusqu’où la compétence reste fiable.

## Utilisateurs

### Personne évaluée

Comprend son niveau réel, ses limites, son incertitude et ses possibilités de progression.

### Évaluateur

Mesure une compétence sans réduire la personne à une note brute.

### Organisation

Peut utiliser une preuve bornée par domaine dans un processus gouverné, avec explication et recours.

### KonnectED / CertifiKation

KonnectED peut utiliser le profil comme contexte d’apprentissage. CertifiKation peut attester un résultat confirmé à partir de l’evidence XKaliber.

### K-Port / EkoH

K-Port peut recevoir une evidence package XKaliber ou une attestation CertifiKation, vérifier son admissibilité et la router vers EkoH. EkoH reste owner du reputation impact.

## Sorties principales

### Caliber Profile

Contient notamment :

- domaine et compétence ;
- niveau confirmé ;
- niveau exploré ;
- confiance/incertitude ;
- forces et limites observées ;
- conditions de validité ;
- recommandations ;
- version des règles ;
- statut et traçabilité.

### Assessment Evidence Package

Projection minimale, vérifiable et partageable du résultat destinée à un consumer autorisé tel que CertifiKation ou K-Port.

Il ne contient pas par défaut toutes les réponses ni tous les détails sensibles de session.

## Non-objectifs

XKaliber ne cherche pas à :

- produire un score universel de mérite ;
- déterminer la valeur globale d’une personne ;
- produire directement un score EkoH ;
- produire directement une reading Smart Vote ;
- remplacer CertifiKation comme authority d’attestation ;
- contourner K-Port pour écrire dans EkoH ;
- automatiser une décision lourde sans recours ;
- imposer un fournisseur, framework ou protocole technique avant que le contract l’exige.

# XKaliber

**L’épreuve qui révèle le vrai calibre.**

XKaliber est l’**application / moteur d’évaluation adaptative des compétences** de la frontière **CertifiKation / KonnectED** dans Konnaxion.

Sa responsabilité est précise : **mesurer une compétence contextualisée et produire une preuve d’évaluation explicable, contestable et bornée par domaine**.

XKaliber n’est pas :

- un ecosystem system peer de Konnaxion ;
- un moteur de réputation ;
- une authority universelle sur la personne ;
- CertifiKation lui-même ;
- K-Port ;
- EkoH ;
- Smart Vote.

## Catégorie architecturale

```text
kOA Digital Ecosystem
└── Konnaxion                         ecosystem system / platform
    └── KonnectED                    domaine/application d’apprentissage
        └── CertifiKation            capacité d’attestation
            └── XKaliber             application + assessment engine

Konnaxion / EkoH boundary
└── K-Port                            evidence gateway vers EkoH
```

Le diagramme fixe les responsabilités. Il ne prescrit pas la topologie de déploiement ni la structure finale des repos.

## Core idea

Un test uniforme mesure en partie l’adaptation de la personne au test. XKaliber cherche plutôt le niveau auquel une compétence reste **fiable**.

Le moteur :

1. estime un point de départ ;
2. confirme une zone de maîtrise ;
3. augmente la difficulté quand le niveau est trop facile ;
4. explore le plafond utile ;
5. s’arrête lorsque le niveau confirmé et l’incertitude sont suffisamment caractérisés ;
6. produit un **Profil de Calibre** et un **Assessment Evidence Package**.

## Ownership

### XKaliber owns

- competency domains used by the assessment contract;
- competency definitions and levels in its assessment scope;
- assessment items/tasks;
- assessment sessions;
- observed responses/performance evidence;
- adaptive rule versions;
- scoring/interpretation used to produce the assessment result;
- `CaliberProfile`;
- `AssessmentEvidencePackage` exported from the assessment;
- assessment audit and contestation state.

### XKaliber does not own

- the CertifiKation attestation/seal lifecycle;
- K-Port evidence admissibility;
- EkoH reputation scores;
- Smart Vote readings or weighting policy;
- Konnaxion civic state;
- KonnectED learning-path state outside the assessment boundary.

## Canonical authority chain

```text
KonnectED develops / tracks learning context
        ↓
XKaliber measures competency
        ↓
Caliber Profile + Assessment Evidence Package
        ↓
CertifiKation attests when applicable
        ↓
XKaliber evidence and/or CertifiKation attestation
        ↓
K-Port qualifies and routes admissible evidence
        ↓
EkoH decides domain-bounded reputation impact
        ↓
Smart Vote may consume governed EkoH context for a declared reading
```

No downstream component re-scores the XKaliber assessment. A contestation of the assessment returns to XKaliber. A contestation of evidence admissibility belongs to K-Port. A contestation of reputation impact belongs to EkoH.

## Design principles

XKaliber remains:

1. **adaptive** — difficulty changes according to observed performance;
2. **explainable** — the assessed person can understand the result;
3. **governable** — rules and thresholds are explicit and versioned;
4. **domain-bounded** — competence in one domain does not grant general authority;
5. **auditable** — relevant inputs, rules and human interventions are traceable;
6. **contestable** — a result can be reviewed, corrected or invalidated;
7. **privacy-conscious** — downstream disclosure is minimized;
8. **exportable** — evidence can leave XKaliber without transferring XKaliber’s ownership of the measurement semantics.

## Technology posture

The repository remains intentionally **technology-agnostic**. It defines product semantics, contracts and acceptance behavior before choosing framework, database, cloud or AI provider.

Technology choices must implement these contracts rather than redefine them.

# XKaliber — Sécurité et confidentialité

## Données sensibles

XKaliber peut manipuler :

- identité/pseudonyme ;
- réponses et productions ;
- résultats d’évaluation ;
- historique de session ;
- commentaires d’évaluateurs ;
- signaux de compétence ;
- traces de performance ;
- audit/contestation ;
- evidence exportée.

## Principes

### Minimisation

Collecter seulement les données nécessaires à l’évaluation, à l’explication et à la preuve autorisée.

### Consentement

La personne doit pouvoir savoir :

- ce qui est évalué ;
- pourquoi ;
- qui verra le résultat ;
- quels détails quittent XKaliber ;
- la durée de conservation/validité applicable ;
- les usages downstream permis.

### Séparation

```text
raw responses / session evidence
≠ scoring interpretation
≠ Caliber Profile
≠ Assessment Evidence Package
≠ CertifiKation attestation
≠ K-Port admissibility decision
≠ EkoH reputation state
≠ Smart Vote reading
```

XKaliber ne stocke pas comme état autoritaire les décisions downstream qui appartiennent à CertifiKation, K-Port, EkoH ou Smart Vote.

### Explicabilité

Le résultat expose les principaux facteurs, limites et règles qui permettent de comprendre le niveau confirmé et l’incertitude.

### Recours

Une personne peut demander une revue, correction, recalibrage ou explication humaine selon le contract applicable.

## Export

Un `AssessmentEvidencePackage` contient le minimum nécessaire au consumer autorisé. Les réponses brutes ne sont pas partagées par défaut avec K-Port, EkoH ou Smart Vote.

## Risques

- biais culturel ou linguistique ;
- surinterprétation ;
- usage hors contexte ;
- pression à rendre public un profil ;
- classement abusif ;
- réutilisation downstream sans consentement ;
- confusion entre compétence technique, réputation et valeur morale.

# XKaliber — Acceptance scenarios

## 1. Avoid ceiling effect

Given a person who succeeds at all easy items, when the assessment runs, the system increases difficulty and the profile distinguishes confirmed level from higher-level exploration.

## 2. Avoid measuring only failure

Given a person started above an informative level, when performance shows the difficulty is poorly calibrated, the engine moves toward a more informative level and preserves the distinction between failure at the higher level and competence at a lower level.

## 3. XKaliber does not self-issue CertifiKation

Given a completed Caliber Profile, when certification is requested, XKaliber exports an `AssessmentEvidencePackage`; CertifiKation makes the attestation decision under its own contract.

## 4. Contest an assessment result

Given a candidate who contests a profile, when review is requested, XKaliber records the reason, opens/records the appropriate review state and does not silently alter the original result without an auditable correction.

## 5. Evidence reaches EkoH through K-Port

Given valid XKaliber assessment evidence intended for reputation use, when it leaves XKaliber, it is handed to K-Port for provenance, scope, consent, mapping and admissibility checks. XKaliber does not write an EkoH score directly.

## 6. Smart Vote does not consume raw XKaliber assessment data

Given XKaliber-derived evidence used in a civic context, Smart Vote receives only governed context through the appropriate EkoH boundary and keeps source/unweighted civic results distinct from a contextual reading.

## 7. Corrections propagate as evidence state changes

Given a corrected/contested/expired XKaliber profile, when downstream evidence exists, XKaliber can export or notify the new source status without directly editing K-Port or EkoH authoritative state.

# XKaliber — Core acceptance checklist

## Assessment

- [ ] A person can understand what is being assessed and why.
- [ ] Consent is recorded for the assessment scope.
- [ ] The engine can start at an estimated level.
- [ ] The engine can increase, reduce or stabilize difficulty.
- [ ] The engine can distinguish confirmed and explored levels.
- [ ] The result includes confidence/uncertainty and validity limits.
- [ ] A person can request review/contestation.

## Evidence

- [ ] XKaliber can create a Caliber Profile.
- [ ] XKaliber can export an Assessment Evidence Package.
- [ ] The evidence package includes source identity, scope, rule version, status, validity/use limits and consent reference as required.
- [ ] Raw responses are not included in downstream evidence by default.
- [ ] XKaliber does not self-issue a CertifiKation-owned seal.
- [ ] XKaliber does not create an EkoH-owned reputation score/signal.

## Governance

- [ ] Domains, competencies, items and assessment rules are versioned.
- [ ] Human interventions are auditable.
- [ ] Result correction/contestation is explicit.
- [ ] Out-of-domain use is prohibited by policy.
